# سطر الأوامر والوكلاء

كل تثبيت يشحن أمر `ieumoffice` يقود المحركات نفسها التي تستخدمها النافذة — المحلّلات نفسها، والكاتب نفسه، والمحرّك نفسه. الملف الذي يحفظه التطبيق والملف الذي يكتبه الأمر هما الملف نفسه، والفحص الذي يجتازه لوحة الذكاء الاصطناعي في التطبيق يجتازه الأمر أيضًا.

```sh
ieumoffice --help          # every command
ieumoffice guide slides    # the op reference, for writing your own
```

يعرض `ieumoffice --help` الواجهة كاملة في شاشة واحدة: كل أمر مع سطر يشرح ما يفعله، ثم الخيارات العامة ورموز الخروج.

## الحصول على الأمر

يأتي الأمر داخل التطبيق. لمناداته بالاسم شغّل `ieumoffice install-cli` مرة واحدة: في Windows يضيف المجلد الذي يحوي الأمر إلى `PATH` الخاص بمستخدمك، فتعثر عليه الطرفيات التي تفتحها بعد ذلك. ويبيّن **الإعدادات ▸ التكاملات** هل تعثر طرفيتك على الأمر بالفعل، وإن لم تكن تعثر عليه فيعرض السطر الذي عليك تشغيله بالضبط.

وكلاء البرمجة لا يحتاجون إلى هذه الخطوة. يسجّل التطبيق موضع الأمر في ‎`~/.ieumoffice/launcher`، وهم يعثرون عليه هناك.

## الأوامر التي تستحق المعرفة

| الأمر             | وظيفته                                                                                                                                                                                        |
| ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `open`            | فتح مستند داخل التطبيق؛ ويشغّل التطبيق إن لم يكن يعمل.                                                                                                                                        |
| `selection`       | ما يختاره المستخدم في ذلك الملف في هذه اللحظة، ما دام التطبيق يعمل — إشارة «هذا» / «هنا». ويعيد نطاق كتل، أو نطاقًا في الجدول، أو عناصر شريحة، أو صفحة، أيًّا كان المحرّر المفتوح عليه الملف. |
| `convert`         | التحويل بين الصيغ باستخدام محركات التطبيق نفسها.                                                                                                                                              |
| `create`          | إنشاء مستند من محتوى منظَّم.                                                                                                                                                                  |
| `render`          | صورة PNG لكل صفحة، بالتخطيط الذي ينفّذه المحرّك.                                                                                                                                              |
| `pdf`             | قراءة الطبقة النصية لملف PDF صفحةً بصفحة، دون أي عملية تطبيق.                                                                                                                                 |
| `read-url`        | قراءة نص صفحة ويب من سطر الأوامر — مقال أو مستند أو رابط في مهارة؛ يطبع النص ويكمل باستخدام `--offset`.                                                                                       |
| `info`            | البيانات الوصفية وملخّص لبنية المستند.                                                                                                                                                        |
| `search`          | بحث في الويب أو عن الصور: البحث المجاني افتراضيًا، أو مزوّد البحث الذي اخترت مفتاحه في التطبيق.                                                                                               |
| `image` / `media` | توليد صورة، أو وصف صورة أو ملف فيديو أو صوتي والسؤال عنه.                                                                                                                                     |
| `merge`           | ملء العناصر النائبة `{{key}}` في قالب `.docx` أو `.pptx` أو `.xlsx`.                                                                                                                          |
| `capabilities`    | الإبلاغ عن ميزات الذكاء الاصطناعي (البحث، وتوليد الصور، وتحليل الصور والفيديو) المتاحة على هذا الجهاز، وعبر أي مسار.                                                                          |
| `guide`           | مرجع العمليات وأدلة التصميم، مولَّد من التعريفات نفسها التي يتحقق منها المنفّذ — لذا لا يمكن أن ينحرف عمّا يقبله `apply`. ويعيد `--json` المرجع مع مخطط كل عملية.                             |
| `install-cli`     | وضع `ieumoffice` في `PATH`.                                                                                                                                                                   |
| `skill`           | عرض وكلاء البرمجة الموجودين على هذا الجهاز وتثبيت مهارة GenOffice فيها أو تحديثها.                                                                                                            |
| `mcp`             | تقديم كل أمر كأداة ضمن Model Context Protocol. انظر **ربط وكيل برمجي**.                                                                                                                       |

## التحرير: مستندات وجداول وعروض

`ieumoffice docs` و`ieumoffice sheet` و`ieumoffice slides` تقرأ وتحرّر عبر مسار الكتابة نفسه الذي يستخدمه التطبيق، وهي تتشارك مفردات واحدة: **العملية** (op) هي تعديل واحد، و**المواصفة** (spec) قائمة عمليات تُطبَّق بالترتيب.

```sh
ieumoffice sheet read report.xlsx
ieumoffice slides apply deck.pptx --ops ops.json --dry-run
ieumoffice docs apply brief.docx --ops ops.json
```

يعرض `--dry-run` ما ستفعله دفعة ولا يكتب شيئًا، وهذه أرخص طريقة للتحقق من مواصفة قبل تطبيقها. ولوحة الذكاء الاصطناعي في التطبيق تعمل على هذه العمليات بالضبط، فأي شيء تطلبه منها يمكنك برمجته.

## أوامر البحث والصور والوسائط

تستخدم `search` و`image` و`media` ما أُعدّ في التطبيق تحت الإعدادات ▸ الذكاء الاصطناعي ▸ خيارات متقدمة:

- `search` يعمل دائمًا. يستخدم البحث المجاني افتراضيًا، أو مزوّد البحث الذي اخترت مفتاحه.
- `image` يحتاج إلى مفتاح مزوّد صور. في هذا الإصدار لا يولّد الاشتراك صورًا.
- `media` مع صورة يستخدم مزوّدًا يعمل بمفتاح حين يكون أحدهم مُعدًّا. ولا يستخدم اشتراك Claude أو Codex لديك إلا إذا سمحت بذلك، وهذا **معطل افتراضيًا**؛ ويشرح [ربط وكيل برمجي](help://mcp) هذا الخيار وحدوده.
- `media` مع فيديو أو صوت يحتاج إلى مزوّد يعمل بمفتاح ويدعم الفيديو.

يبلّغ `ieumoffice capabilities --json` عن ذلك كله من دون استدعاء أي ذكاء اصطناعي. ويحوي الحقل `detail` فيه:

| الحقل                                                                            | ما يقوله                                                                                                                                                                                                                    |
| -------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `search`, `image_search`, `image_generation`, `image_analysis`, `video_analysis` | لكل ميزة: `available`؛ و`via`، أي مَن يجيب؛ و`route`، وهو أحد `free` أو `key` أو `subscription`؛ و`metered: true` لتسجيل دخول بالدفع حسب الاستخدام؛ وحين لا تكون الميزة متاحة، `message`، وهو النص الذي يجيب به الأمر نفسه. |
| `media_analysis`                                                                 | مُبقى من أجل السكربتات القديمة: يطابق `image_analysis`، أو `video_analysis` حين يعمل الفيديو وحده.                                                                                                                          |
| `automatic_calls`                                                                | `subscription_enabled`، وما دام مفعّلًا، `used` وهو عدد الطلبات التلقائية التي عولجت في الساعة الأخيرة (للعلم فقط)، أما `limit` و`remaining` فقيمتهما `null` دائمًا.                                                        |
| `app`                                                                            | `available`: هل التطبيق مثبَّت حيث يستطيع الأمر تشغيله.                                                                                                                                                                     |
| `settings_path`                                                                  | ملف الإعدادات الذي قُرئت منه هذه الإجابات.                                                                                                                                                                                  |

حين يتعذّر تشغيل `image` أو `media`، ينتهي الأمر برمز الخروج 4 ومعه `error: "app_unavailable"`‎، ويذكر `detail.errorCode` السبب. ويعني `unavailable` أن لا شيء مُعدّ لهذه الميزة، فلن تفيد إعادة المحاولة. أما `rate-limit` فيأتي مع `detail.resetsAt`، وهو الوقت (بالميلي ثانية) الذي تصبح فيه الطلبات ممكنة من جديد.

## ما الذي يحتفظ به على هذا الحاسوب

الملفان كلاهما في المجلد ‎`.ieumoffice` داخل مجلد المستخدم لديك:

- ‎`~/.ieumoffice/launcher` يسجّل موضع أمر التطبيق، فيعثر عليه وكيل البرمجة حتى إن لم يكن في `PATH` لديك.
- ‎`~/.ieumoffice/cli-audit.jsonl` يُضاف إليه سطر لكل أمر شُغّل — الأمر ووسائطه ونتيجته — لتتمكن لاحقًا من رؤية ما فعله الوكيل.

## Model Context Protocol

يقدّم `ieumoffice mcp` كل أمر كأداة MCP، ويسجّل `ieumoffice mcp install <agent|all>` في إعداد وكيل البرمجة نفسه. انظر **ربط وكيل برمجي** لتلك الجهة.

## ما لا يفعله الأمر

هو يقرأ الملف ويكتبه. لكنه ليس التطبيق: لا توجد نافذة، ولا ينطبق حوار التحديث داخل التطبيق. وأي شيء يحتاج إلى النافذة — لوحة الذكاء الاصطناعي، أو مراجعة الجودة QC لشريحة مُعرضة — عليه أن ينتظر حتى تفتح الملف. ويمنحك `ieumoffice render` البكسلات دون ذلك، وتُدقّق `ieumoffice slides` في تخطيط العرض بنفسها.
