# שורת פקודה וסוכנים

כל התקנה כוללת פקודת `ieumoffice` שמנהלת את אותם מנועים שהחלון משתמש בהם — אותם מנתחים, אותו כותב, אותו מרונדר. קובץ שהאפליקציה שומרת וקובץ שהפקודה כותבת הם אותו קובץ, ובדיקה שחלונית ה-AI של האפליקציה עוברת היא בדיקה שגם הפקודה עוברת.

```sh
ieumoffice --help          # every command
ieumoffice guide slides    # the op reference, for writing your own
```

‏`ieumoffice --help` מציג את כל הממשק במסך אחד: כל פקודה עם שורה שמסבירה מה היא עושה, ואז האפשרויות הגלובליות וקודי היציאה.

## קבלת הפקודה

הפקודה מגיעה בתוך האפליקציה. כדי לקרוא לה בשם, הריצו פעם אחת `ieumoffice install-cli`: ב-Windows היא מוסיפה את התיקייה שבה נמצאת הפקודה ל-`PATH` של המשתמש שלכם, ומסופים שתפתחו אחר כך ימצאו אותה. **הגדרות ▸ שילובים** מראה אם המסוף שלכם כבר מוצא את הפקודה, ואם לא — את השורה המדויקת שצריך להריץ.

סוכני תכנון אינם צריכים את השלב הזה. האפליקציה רושמת את מיקום הפקודה ב-‎`~/.ieumoffice/launcher`, והם מוצאים אותה שם.

## הפקודות שכדאי להכיר

| פקודה             | מה היא עושה                                                                                                                                                             |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `open`            | פותחת מסמך באפליקציה; מפעילה את האפליקציה אם היא לא רצה.                                                                                                                |
| `selection`       | מה שהמשתמש בחר בקובץ הזה עכשיו, כל עוד האפליקציה רצה — זו ההצבעה על ״זה״ / ״כאן״. לוקחת טווח בלוקים, טווח בגיליון, אלמנטים בשקופית או עמוד, בהתאם לעורך שבו נמצא הקובץ. |
| `convert`         | ממירה בין פורמטים באמצעות המנועים של האפליקציה עצמה.                                                                                                                    |
| `create`          | יוצרת מסמך מתוכן מובנה.                                                                                                                                                 |
| `render`          | PNG אחד לכל עמוד, לפי הפריסה של המרונדר.                                                                                                                                |
| `pdf`             | קוראת את שכבת הטקסט של PDF עמוד אחר עמוד, בלי תהליך של האפליקציה.                                                                                                       |
| `read-url`        | קוראת את הטקסט של דף אינטרנט משורת הפקודה — מאמר, מסמך או קישור של מיומנות; מדפיסה את הטקסט וממשיכה עם `--offset`.                                                      |
| `info`            | מטא-נתונים ותקציר מבנה של מסמך.                                                                                                                                         |
| `search`          | חיפוש ברשת או חיפוש תמונות: החיפוש החינמי כברירת מחדל, או ספק החיפוש שאת המפתח שלו בחרתם באפליקציה.                                                                     |
| `image` / `media` | יוצרת תמונה, או מתארת קובץ תמונה, וידאו או שמע ועונה עליו שאלות.                                                                                                        |
| `merge`           | ממלאת מציידי מקום `{{key}}` בתבנית `.docx`, `.pptx` או `.xlsx`.                                                                                                         |
| `capabilities`    | מדווחת אילו תכונות AI (חיפוש, יצירת תמונות, ניתוח תמונות ווידאו) זמינות במחשב הזה, ובאיזה מסלול.                                                                        |
| `guide`           | מפניית הפעולות ומדריכי העיצוב, נוצרות מאותם הגדרות שמולן המבצע מאמת — ולכן היא לא יכולה לסטות ממה ש-`apply` מקבל. `--json` מחזיר אותה עם הסכמה של כל פעולה.             |
| `install-cli`     | מציבה את `ieumoffice` ב-`PATH`.                                                                                                                                         |
| `skill`           | מפרטת את סוכני התכנון שנמצאו במחשב הזה ומתקינה בהם או מעדכנת את המיומנות של GenOffice.                                                                                  |
| `mcp`             | מגישה כל פקודה ככלי ב- Model Context Protocol. ראו **חיבור סוכן תכנון**.                                                                                                |

## עריכה: מסמכים, גיליונות, מצגות

‏`ieumoffice docs`, ‏`ieumoffice sheet` ו-`ieumoffice slides` קוראות ועורכות דרך אותו נתיב כתיבה שהאפליקציה עצמה משתמשת בו, והן חולקות מילון אחד: **פעולה** (op) היא עריכה בודדת, ו**מפרט** (spec) הוא רשימת פעולות המיושמות לפי הסדר.

```sh
ieumoffice sheet read report.xlsx
ieumoffice slides apply deck.pptx --ops ops.json --dry-run
ieumoffice docs apply brief.docx --ops ops.json
```

‏`--dry-run` מדווח מה אצווה הייתה עושה ולא כותב דבר, וזו הדרך הזולה לבדוק מפרט לפני שהוא נופל. חלונית ה-AI של האפליקציה רצה בדיוק על אותן פעולות, ולכן כל מה שאתם יכולים לבקש ממנה אפשר גם לתסריט.

## פקודות החיפוש, התמונות והמדיה

‏`search`, ‏`image` ו-`media` משתמשות במה שהוגדר באפליקציה תחת הגדרות ▸ AI ▸ מתקדם:

- ‏`search` פועלת תמיד. היא משתמשת בחיפוש החינמי כברירת מחדל, או בספק החיפוש שאת המפתח שלו בחרתם.
- ‏`image` דורשת מפתח של ספק תמונות. בגרסה הזו מינוי אינו יוצר תמונות.
- ‏`media` על תמונה משתמשת בספק עם מפתח כשמוגדר כזה. היא משתמשת במינוי Claude או Codex שלכם רק אם אישרתם זאת, וזה **כבוי כברירת מחדל**; [חיבור סוכן לקוד](help://mcp) מסביר את המתג ואת המגבלות שלו.
- ‏`media` על וידאו או שמע דורשת ספק עם מפתח שתומך בווידאו.

‏`ieumoffice capabilities --json` מדווחת על כל זה בלי לפנות לשום AI. השדה `detail` שלה מכיל:

| שדה                                                                              | מה הוא אומר                                                                                                                                                                                          |
| -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `search`, `image_search`, `image_generation`, `image_analysis`, `video_analysis` | לכל תכונה: `available`; ‏`via`, מי עונה; ‏`route`, אחד מבין `free`, ‏`key` או `subscription`; ‏`metered: true` לכניסה בתשלום לפי שימוש; וכשהתכונה אינה זמינה, `message`, הטקסט שהפקודה עצמה עונה בו. |
| `media_analysis`                                                                 | נשמר בשביל סקריפטים ישנים: זהה ל-`image_analysis`, או ל-`video_analysis` כשרק וידאו פועל.                                                                                                            |
| `automatic_calls`                                                                | ‏`subscription_enabled`, וכל עוד הוא מופעל, `used`, מספר הבקשות האוטומטיות שטופלו בשעה האחרונה (לידיעה בלבד); ‏`limit` ו-`remaining` הם תמיד `null`.                                                 |
| `app`                                                                            | ‏`available`: האם האפליקציה מותקנת במקום שממנו הפקודה יכולה להפעיל אותה.                                                                                                                             |
| `settings_path`                                                                  | קובץ ההגדרות שממנו נקראו התשובות האלה.                                                                                                                                                               |

כש-`image` או `media` אינן יכולות לרוץ, הפקודה מסתיימת בקוד יציאה 4 ועם `error: "app_unavailable"`‎, ו-`detail.errorCode` מסביר למה. ‏`unavailable` פירושו ששום דבר לא הוגדר עבור התכונה, ולכן ניסיון נוסף לא יעזור. ‏`rate-limit` מגיע עם `detail.resetsAt`, המועד (באלפיות שנייה) שבו שוב אפשר לשלוח בקשות.

## מה היא שומרת במחשב הזה

שני הקבצים נמצאים בתיקייה ‎`.ieumoffice` שבתוך תיקיית המשתמש שלכם:

- ‎`~/.ieumoffice/launcher` רושם איפה נמצאת הפקודה של האפליקציה, כך שסוכן תכנון מוצא אותה גם כשהיא אינה ב-`PATH` שלכם.
- ‎`~/.ieumoffice/cli-audit.jsonl` מקבל שורה אחת על כל פקודה שהורצה — הפקודה, הארגומנטים שלה והתוצאה — כך שאפשר לראות בדיעבד מה סוכן עשה.

## Model Context Protocol

‏`ieumoffice mcp` מגישה כל פקודה ככלי MCP, ו-`ieumoffice mcp install <agent|all>` רושמת אותה בהגדרות של סוכן התכנון עצמו. ראו **חיבור סוכן תכנון** לצד הזה.

## מה שהפקודה אינה עושה

היא קוראת את הקובץ וכותבת אותו. היא אינה האפליקציה: אין חלון, וחלונית העדכון שבאפליקציה אינה חלה. כל מה שדורש את החלון — חלונית ה-AI, ביקורת האיכות על שקופית מרונדרת — חייב לחכות שתפתחו את הקובץ. ‏`ieumoffice render` נותן לכם את הפיקסלים בלי זה, ו-`ieumoffice slides` בודקת את הפריסה של מצגת בעצמה.
