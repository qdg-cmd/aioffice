# บรรทัดคำสั่งและเอเจนต์

ทุกการติดตั้งมีคำสั่ง `ieumoffice` ที่ใช้เอนจินชุดเดียวกับหน้าต่าง ตัวแยกเอกสารชุดเดียวกัน ตัวเขียนไฟล์ชุดเดียวกัน ตัวเรนเดอร์ชุดเดียวกัน ไฟล์ที่แอปบันทึกกับไฟล์ที่คำสั่งเขียน คือไฟล์เดียวกัน และการตรวจที่ผ่านในแผง AI ก็คือการตรวจที่คำสั่งผ่านเช่นกัน

```sh
ieumoffice --help          # every command
ieumoffice guide slides    # the op reference, for writing your own
```

`ieumoffice --help` แสดงทั้งหมดไว้ในหน้าจอเดียว: ทุกคำสั่งมีบรรทัดบอกว่ามันทำอะไร ตามด้วยตัวเลือกทั่วไปและรหัสการจบการทำงาน

## หาคำสั่งมาใช้

คำสั่งนี้มาพร้อมกับแอป จะเรียกใช้ตามชื่อให้รัน `ieumoffice install-cli` ครั้งเดียว: บน Windows คำสั่งนี้จะเพิ่มโฟลเดอร์ที่เก็บคำสั่งเข้าไปใน `PATH` ของผู้ใช้ แล้วเทอร์มินัลที่คุณเปิดหลังจากนั้นจะหาคำสั่งเจอ **การตั้งค่า ▸ การเชื่อมต่อ** จะแสดงว่าเทอร์มินัลของคุณหาคำสั่งเจอแล้วหรือยัง และถ้ายังไม่เจอ ก็จะแสดงบรรทัดที่ต้องรันให้ตรงตัว

เอเจนต์เขียนโค้ดไม่ต้องทำขั้นตอนนี้ แอปจะบันทึกตำแหน่งของคำสั่งไว้ใน `~/.ieumoffice/launcher` แล้วเอเจนต์จะหาคำสั่งเจอจากที่นั่น

## คำสั่งที่ควรรู้จัก

| คำสั่ง            | ทำอะไร                                                                                                                                                                                                  |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `open`            | เปิดเอกสารในแอป ถ้ายังไม่ได้รันก็จะสั่งให้แอปเริ่มทำงาน                                                                                                                                                 |
| `selection`       | สิ่งที่ผู้ใช้เลือกไว้ในไฟล์นั้น ณ ตอนนี้ ขณะที่แอปยังทำงานอยู่ นี่คือตัวชี้ของ "ตัวนี้" / "ตรงนี้" คำสั่งนี้คืนช่วงบล็อก ช่วงเซลล์ในชีต องค์ประกอบของสไลด์ หรือหนึ่งหน้า ตามตัวแก้ไขที่เปิดไฟล์นั้นอยู่ |
| `convert`         | แปลงรูปแบบโดยใช้เอนจินของตัวแอปเอง                                                                                                                                                                      |
| `create`          | สร้างเอกสารจากเนื้อหาที่มีโครงสร้าง                                                                                                                                                                     |
| `render`          | ได้ PNG หนึ่งไฟล์ต่อหนึ่งหน้า ตามที่ตัวเรนเดอร์วางหน้ากระดาษ                                                                                                                                            |
| `pdf`             | อ่านชั้นข้อความของ PDF ทีละหน้า โดยไม่ต้องเปิดโปรแกรม                                                                                                                                                   |
| `read-url`        | อ่านข้อความของหน้าเว็บจากบรรทัดคำสั่ง — บทความ เอกสาร หรือลิงก์ในสกิล พิมพ์ข้อความออกมาและอ่านต่อด้วย `--offset`                                                                                        |
| `info`            | ข้อมูลเมตาดาต้าและสรุปโครงสร้างของเอกสาร                                                                                                                                                                |
| `search`          | ค้นบนเว็บหรือค้นรูป: ใช้การค้นหาฟรีเป็นค่าเริ่มต้น หรือใช้ผู้ให้บริการค้นหาที่คุณเลือกคีย์ไว้ในแอป                                                                                                      |
| `image` / `media` | สร้างรูป หรืออธิบายและถามคำถามเกี่ยวกับไฟล์รูป วิดีโอ หรือเสียง                                                                                                                                         |
| `merge`           | เติมค่าในตัวแทน `{{key}}` ของเทมเพลต `.docx`, `.pptx` หรือ `.xlsx`                                                                                                                                      |
| `capabilities`    | รายงานว่าเครื่องนี้ใช้ฟีเจอร์ AI อะไรได้บ้าง (การค้นหา การสร้างภาพ การวิเคราะห์ภาพและวิดีโอ) และใช้ผ่านเส้นทางใด                                                                                        |
| `guide`           | คู่มือ op และแนวทางการออกแบบ สร้างจากนิยามชุดเดียวกับที่ตัว executor ใช้ตรวจ จึงเลื่อนจากสิ่งที่ `apply` รับได้ไม่ได้ `--json` จะคืนคู่มือพร้อมสคีมาของแต่ละ op                                         |
| `install-cli`     | เอา `ieumoffice` ไปไว้ใน `PATH`                                                                                                                                                                         |
| `skill`           | รายชื่อเอเจนต์เขียนโค้ดที่เจอบนเครื่องนี้ และติดตั้งหรืออัปเดต skill ของ GenOffice เข้าไปในเอเจนต์เหล่านั้น                                                                                             |
| `mcp`             | เปิดทุกคำสั่งเป็นเครื่องมือ Model Context Protocol ดู **การเชื่อมต่อเอเจนต์เขียนโค้ด**                                                                                                                  |

## การแก้ไข เอกสาร ชีต และสไลด์

`ieumoffice docs`, `ieumoffice sheet` และ `ieumoffice slides` อ่านและเขียนผ่านช่องทางเดียวกับที่แอปใช้ และใช้คำศัพท์ชุดเดียวกัน **op** คือการแก้ไขหนึ่งครั้ง ส่วน **spec** คือรายการของ op ที่จะถูกใช้ตามลำดับ

```sh
ieumoffice sheet read report.xlsx
ieumoffice slides apply deck.pptx --ops ops.json --dry-run
ieumoffice docs apply brief.docx --ops ops.json
```

`--dry-run` จะบอกว่าชุดงานนี้จะทำอะไร และไม่เขียนอะไรลงเลย นี่คือวิธีที่ถูกในการตรวจสอบ spec ก่อนใช้จริง แผง AI ในแอปทำงานบน op ชุดนี้พอดี คุณสั่งมันได้อะไร ก็เขียนสคริปต์ให้มันทำได้อะไร

## คำสั่งค้นหา ภาพ และสื่อ

`search`, `image` และ `media` ใช้สิ่งที่ตั้งค่าไว้ในแอปใต้ การตั้งค่า ▸ AI ▸ ขั้นสูง:

- `search` ใช้ได้เสมอ โดยใช้การค้นหาฟรีเป็นค่าเริ่มต้น หรือใช้ผู้ให้บริการค้นหาที่คุณเลือกคีย์ไว้
- `image` ต้องใช้คีย์ของผู้ให้บริการสร้างภาพ ในเวอร์ชันนี้การสมัครสมาชิกสร้างภาพไม่ได้
- `media` กับภาพ จะใช้ผู้ให้บริการแบบใช้คีย์เมื่อมีการตั้งค่าไว้ และจะใช้การสมัครสมาชิก Claude หรือ Codex ของคุณก็ต่อเมื่อคุณอนุญาตไว้เท่านั้น ซึ่ง **ปิดโดยค่าเริ่มต้น** โดย [เชื่อมต่อเอเจนต์เขียนโค้ด](help://mcp) อธิบายสวิตช์นี้และข้อจำกัดของมัน
- `media` กับวิดีโอหรือเสียง ต้องใช้ผู้ให้บริการแบบใช้คีย์ที่รองรับวิดีโอ

`ieumoffice capabilities --json` รายงานทั้งหมดนี้โดยไม่เรียก AI ใด ๆ เลย ใน `detail` มีข้อมูลดังนี้:

| ฟิลด์                                                                            | ความหมาย                                                                                                                                                                                                                                                  |
| -------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `search`, `image_search`, `image_generation`, `image_analysis`, `video_analysis` | สำหรับแต่ละฟีเจอร์: `available`; `via` คือผู้ที่ตอบ; `route` เป็นค่าใดค่าหนึ่งใน `free`, `key` หรือ `subscription`; `metered: true` สำหรับการเข้าสู่ระบบแบบจ่ายตามการใช้งาน; และเมื่อฟีเจอร์ใช้ไม่ได้ จะมี `message` ซึ่งเป็นข้อความที่ตัวคำสั่งเองใช้ตอบ |
| `media_analysis`                                                                 | เก็บไว้สำหรับสคริปต์รุ่นเก่า: มีค่าเหมือน `image_analysis` หรือเหมือน `video_analysis` เมื่อใช้ได้เฉพาะวิดีโอ                                                                                                                                             |
| `automatic_calls`                                                                | `subscription_enabled` และขณะที่ค่านี้เปิดอยู่ จะมี `used` ซึ่งเป็นจำนวนคำขออัตโนมัติที่จัดการในหนึ่งชั่วโมงที่ผ่านมา (เพื่อทราบเท่านั้น) ส่วน `limit` และ `remaining` เป็น `null` เสมอ                                                                   |
| `app`                                                                            | `available`: แอปติดตั้งอยู่ในตำแหน่งที่คำสั่งเรียกให้เริ่มทำงานได้หรือไม่                                                                                                                                                                                 |
| `settings_path`                                                                  | ไฟล์การตั้งค่าที่ใช้อ่านคำตอบเหล่านี้                                                                                                                                                                                                                     |

เมื่อ `image` หรือ `media` ทำงานไม่ได้ คำสั่งจะจบด้วยรหัส 4 และ `error: "app_unavailable"` โดย `detail.errorCode` จะบอกสาเหตุ `unavailable` หมายความว่ายังไม่ได้ตั้งค่าอะไรไว้สำหรับฟีเจอร์นั้น ลองใหม่ก็ไม่ช่วยอะไร ส่วน `rate-limit` จะมาพร้อมกับ `detail.resetsAt` ซึ่งเป็นเวลา (หน่วยมิลลิวินาที) ที่จะส่งคำขอได้อีกครั้ง

## สิ่งที่เก็บไว้ในคอมพิวเตอร์เครื่องนี้

ทั้งสองไฟล์อยู่ในโฟลเดอร์ `.ieumoffice` ภายในโฟลเดอร์ผู้ใช้ของคุณ:

- `~/.ieumoffice/launcher` บันทึกว่าคำสั่งของแอปอยู่ที่ไหน เอเจนต์เขียนโค้ดจึงหาคำสั่งเจอแม้คำสั่งจะไม่อยู่ใน `PATH` ของคุณ
- `~/.ieumoffice/cli-audit.jsonl` จะได้รับหนึ่งบรรทัดต่อทุกคำสั่งที่ถูกรัน — ตัวคำสั่ง อาร์กิวเมนต์ และผลลัพธ์ — คุณจึงดูย้อนหลังได้ว่าเอเจนต์ทำอะไรไปบ้าง

## Model Context Protocol

`ieumoffice mcp` จะเปิดทุกคำสั่งเป็นเครื่องมือ MCP ส่วน `ieumoffice mcp install <agent|all>` จะลงทะเบียนไว้ในค่าตั้งของเอเจนต์เขียนโค้ดแต่ละตัว เรื่องฝั่งนั้นดู **การเชื่อมต่อเอเจนต์เขียนโค้ด**

## สิ่งที่คำสั่งนี้ทำไม่ได้

คำสั่งนี้อ่านและเขียนไฟล์ได้ แต่มันไม่ใช่แอป ไม่มีหน้าต่าง และกล่องอัปเดตในแอปก็ใช้ไม่ได้ สิ่งที่ต้องใช้หน้าต่าง เช่น แผง AI หรือการตรวจคุณภาพสไลด์ที่เรนเดอร์แล้ว ต้องรอคุณเปิดไฟล์ก่อน `ieumoffice render` ให้ค่าพิกเซลได้โดยไม่ต้องมีหน้าต่าง ส่วน `ieumoffice slides` ตรวจเลย์เอาต์ของงานนำเสนอเองได้
