# 0052 — 다른 회사의 로고와 닮은 그림을 쓰지 않고, 고지는 사용자가 실제로 보는 곳에 둔다

## 맥락

2026-10-22 이음오피스가 기사와 SNS에 오르내리면서, 저작권·상표 문제를 미리 정리하기로 했다. 저장소를 점검해 보니 출처 고지 자체(`NOTICE`, README의 "라이선스와 출처")는 갖춰져 있었지만, 그 고지가 사용자에게 실제로 가는 곳에는 빠져 있었다.

- 앱 도움말 그림 20장이 원본 GenOffice 화면을 찍은 것이었다. 홈 탭 이름, 로고, 원본 계정 단추, 원본 저장소 주소가 보였다. Apache License 2.0 6조는 원작자의 상표를 출처를 밝히는 데만 쓰게 한다.
- 설치본에 루트의 `LICENSE`와 `NOTICE`가 들어가지 않았다(4조 (a)(d)). 앱 안 고지 파일의 제목도 원본 이름이었다. 고지 생성기는 `LICENSE-MIT`처럼 이름 붙은 라이선스 파일을 놓쳐 Rust 크레이트 대부분의 저작권 문구를 빠뜨렸다.
- 설정의 AI 제공자 목록이 Anthropic·OpenAI·Google 등의 로고를 썼다. "두 회사의 로고를 쓰지 않는다"(`business-rules.md`)와 어긋났다.
- 파일 아이콘이 다른 회사 것과 닮았다. PDF는 Adobe Acrobat 심볼, 한글은 한컴 한글 앱 아이콘, 워드·엑셀·파워포인트는 Microsoft Office의 색과 글자 체계였다. 탐색기 파일 연결에도 쓰여 PC 전체에서 보인다.
- 앱 화면, 소개 사이트 어디에도 상표·비제휴 고지, 보증하지 않음, 권리자 연락처가 없었다. 도움말은 "Word, Excel, PowerPoint와 완전히 호환된다"고 적었다.
- GitHub 저장소 소개가 원본 문구 그대로였고 홈페이지 링크가 원본 회사 사이트였다.

같은 날 "이 정도면 팔아도 되겠다"는 이야기를 두고 받은 의견도 있었다. 무료 배포는 라이선스상 문제없지만, 판매로 넘어가면 원작 회사의 이름·로고 같은 상표 문제와 한글 처리 부분을 공들여 공개한 rhwp 기여자들과의 관계를 짚어야 한다는 내용이다.

## 결정

**다른 회사의 로고나 그 로고를 닮은 그림을 쓰지 않는다. 출처·상표·보증 고지와 연락처는 사용자가 실제로 보는 곳(설치본, 앱의 설정 → 정보, 소개 사이트)에 둔다.**

- 도움말 그림은 이음오피스 화면으로 다시 찍는다. 본문이 쓰지 않는 그림은 지운다. 도움말 그림 묶음은 모두 설치본에 들어가기 때문이다.
- 설치본에 `LICENSE.txt`, `NOTICE.txt`, `LICENSE-UNICODE.txt`를 넣는다. `THIRD-PARTY-NOTICES.txt`는 맨 앞에 `NOTICE` 전문을 싣고, 제목은 이음오피스로 한다. 라이선스 파일 이름 규칙을 넓히고, WASM 안에 든 C 라이브러리 고지와 템플릿 글꼴을 더한다.
- AI 제공자 표시는 일반 그림 세 가지로만 한다. Codex 구독은 터미널, API 키 제공자는 열쇠, 직접 입력과 Claude 구독은 조절 막대다. 제공자 이름은 그림 옆 글자로 적는다.
- 파일 아이콘은 이 저장소가 새로 그린 한 벌("깔끔한 등판")로 바꾼다. 모서리가 둥근 흰 문서 왼쪽에 진한 형식 색 등판을 두고, 가운데에 내용을 나타내는 굵은 기호 하나(글줄, 칸, 오르는 선, 글줄과 도장 점, "가", #, </>, 마디 셋, { })만 넣는다. 확장자 글자, 고리, 접힌 모서리, 테두리는 없다. 다른 회사의 글자 하나 모양(W·X·P·ㅎ)과 리본 그림을 쓰지 않는다. 기준은 `tools/gen-file-association-icons.mjs` 하나이고, 탭 아이콘도 같은 SVG를 쓴다.
- 설정 → 정보에 다음을 21개 언어로 둔다. 오픈소스 라이선스 보기 단추, 상표·저작권 문의 주소(pblsketch@gmail.com)와 메일 쓰기 단추, rhwp 출처와 한컴 공개 문서 문구, 상표·비제휴 고지, 보증하지 않음과 AI 결과물 확인 안내.
- README에 공식 배포처(GitHub 릴리스, ieumoffice.com), 다시 배포할 때의 조건, 보증하지 않음, 문의 주소를 적는다. 다시 배포할 때의 조건은 `LICENSE`·`NOTICE`를 함께 넣고, 고친 사실을 밝히고, 이름·로고를 자기 제품 이름처럼 쓰지 않는 것이다. `SECURITY.md`와 `NOTICE`에도 문의 주소를 둔다.
- 도움말과 소개 사이트는 형식 이름으로 말한다("워드 파일(.docx)을 열고 저장한다"). "완전히 호환", "○○ 없이" 같은 비교·대체 표현을 쓰지 않는다.
- 문의 주소는 `packages/i18n/src/product.ts`의 `PRODUCT_CONTACT_EMAIL` 한 곳에서 정한다.

## 버린 대안

- **제공자마다 글자 머리글자 표시(A, G, OR …)**: 구별은 쉽지만, 그림 안 글자가 제공자 이름 글에 섞여 읽혔다(화면 글을 읽는 시험이 잡았다). 이름은 이미 옆에 적혀 있어 열쇠 하나로 충분하다.
- **회사 로고를 그대로 두고 허락을 받는다**: 제공자가 스물 남짓이고, 회사마다 로고 사용 지침이 다르다. 허락을 받아도 지침이 바뀔 때마다 따라가야 한다.
- **색 띠에 확장자 글자만 넣은 문서 아이콘**: 처음 적용한 모양이다. 저장소 주인이 너무 평범하다고 해서, 문서 위 그림 기호·브랜드 고리 타일·공책 등판 세 시안 중 공책 등판을 골랐다. 고리 타일은 앱 아이콘과 헷갈렸다.
- **고리와 확장자 글자를 단 공책 등판**: 두 번째로 적용한 모양이다. 저장소 주인이 지저분하다고 해서 요소를 줄인 세 시안(깔끔한 등판, 옅은 색 문서, 선 기호) 중 깔끔한 등판을 골랐다. 옅은 색 문서는 어두운 바탕에서 떠 보였고, 선 기호는 16px에서 가늘었다.
- **파일 아이콘은 업계 관행이니 둔다**: 워드·엑셀 쪽은 흔한 관행이지만, PDF와 한글 아이콘은 특정 회사의 앱 아이콘과 거의 같았다. 하나만 바꾸면 한 벌이 어긋나서 모두 바꿨다.
- **"이음오피스는 판매하지 않는다"고 못 박는다**: 앞으로의 배포 방식은 저장소 주인이 정할 일이다. 지금 사실인 "공식 배포는 무료이고 배포처는 두 곳"만 적었다.

## 결과

- 화면에 다른 회사 로고나 그것을 닮은 그림이 남지 않는다. 새 그림을 들일 때도 같은 기준을 따른다(`standards.md`의 "상표와 아이콘").
- 설치본만 받은 사람도 라이선스 전문, 원작 고지, 수정 사실, 타사 고지를 볼 수 있다. 앱에서는 설정 → 정보의 단추로 연다.
- 파일 아이콘이 바뀌어 사용자 PC의 탐색기 아이콘 모양도 다음 설치 때 바뀐다.
- "이음오피스" 이름의 상표 등록은 하지 않았다. 등록 여부는 저장소 주인이 변리사와 상의해 정한다.
