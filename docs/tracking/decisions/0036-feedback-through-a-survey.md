# 0036 — 의견은 앱 밖 설문으로 받고, 앱은 아무것도 보내지 않는다

## 맥락

사용자가 문제를 겪거나 바라는 점을 알릴 창구가 없었다. 화면에는 "GenOffice를 기반으로 합니다" 고지와 GitHub 저장소 버튼(설정 → 정보)뿐이고, 도움말 메뉴에는 사용 설명서·타사 고지·업데이트 확인·정보만 있었다. 저장소의 `GITHUB_NEW_ISSUE_URL`은 정의만 되어 있고 쓰이지 않았다.

이 앱에는 서버도, 회원 계정도, 사용 통계도 없다(`PRIVACY.md`). 앱이 의견을 직접 모아 두는 구조는 만들 수 없다. 문의 주소나 메일 수신함도 아직 없다.

선택지:

- **GitHub Issues.** 저장소가 이미 있고 이슈 템플릿도 있다(`CONTRIBUTING.md`). 개발자에게는 가장 정확하지만 GitHub 계정이 필요해 일반 사용자에게는 문턱이 높다. 이 앱의 사용자는 특정 직업군이 아니라 누구나다.
- **앱 안 창에 적고 로컬 파일로 저장.** 사용자가 그 파일을 어디론가 보내야 해서 실제로 도착하지 않는다.
- **자체 서버나 설문 백엔드.** 이 앱은 서버를 두지 않기로 했고, 그 판단이 저장소 전체의 전제다.
- **Google 설문(Forms).** 계정 없이 링크만 열면 응답할 수 있고, 저장소 주인이 표 하나로 답을 본다. 앱은 링크만 열면 되므로 새 코드가 거의 없다.

## 결정

**설문 하나를 창구로 둔다.** 저장소 주인이 Google 설문을 만들어 링크를 고정하고, 앱은 그 링크만 연다. 창구는 두 곳이다. 모든 탭의 **도움말 메뉴**와 **설정 → 정보**. 두 곳 모두 같은 뒷단 함수 하나(`openFeedbackSurvey`)로 들어간다.

**보여 주고, 복사한 뒤, 연다.** 설문은 앱이 값을 미리 채워 줄 수 없다(설문의 항목 ID가 있어야 한다). 그래서 앱이 채울 수 있는 것 — 제품 버전, 운영체제, 화면 언어 — 을 먼저 대화 상자에 그대로 보여 주고, "설문 열기"를 누르면 그 세 줄을 클립보드에 복사한 다음 브라우저로 설문을 연다. 사용자는 붙여 넣기만 하면 된다. 앱이 보내는 것은 없고, 클립보드에 들어가는 것도 이 세 줄뿐이다.

**보내지 않는 것.** 문서 내용, 파일 경로, 파일 이름, 열린 탭, 계정, 크래시 기록은 넣지 않는다. 크래시 기록을 함께 보내는 것은 필요해지면 그때 따로 결정한다. 진단 줄에 경로처럼 보이는 값이 들어가지 않는 것은 테스트가 지킨다(`apps/shell/tests/feedback.test.ts`).

**모든 탭에 붙인다.** 편집기마다 메뉴를 따로 만들기 때문에, 메뉴를 만든 뒤 끼워 넣는 자리(`withHelpItems`, 옛 `withUserGuide`)를 넓혀 사용 설명서와 의견 보내기를 함께 넣는다. 새 탭 종류가 생겨도 자동으로 붙는다.

**개인정보 문서에 적는다.** `PRIVACY.md`의 "What leaves your PC" 표에 한 줄을 넣는다. 앱이 직접 보내는 것은 없지만, 설문 페이지에 적은 내용은 Google로 간다.

## 택하지 않은 것

- **GitHub Issues 링크.** 개발자에게는 낫지만 GitHub 계정이 없는 사용자를 처음부터 배제한다. 나중에 개발자용 창구를 더하더라도 이 결정을 대체하지 않는다.
- **앱 안에 적는 창과 로컬 저장.** 실제로 도착하지 않는 창구는 없는 것과 같다.
- **설문 대신 메일 보내기(`mailto:`).** 받는 주소가 공개되어 스팸에 노출되고, 어느 주소로 받을지도 정해지지 않았다.
- **설문 항목을 미리 채우는 링크(`entry.` 매개변수).** 설문을 만든 뒤에야 항목 ID를 알 수 있고, 설문을 고치면 ID가 바뀌어 조용히 깨진다. 복사와 붙여 넣기로 대신한다.
- **익명 사용 통계.** 없애기로 한 기능이고(`tests/removed-features.test.ts`), 사용자가 스스로 누를 때만 나가는 이 창구와는 다르다.
- **설문에 파일 업로드 문항.** 스크린샷을 바로 올릴 수 있지만, 그 문항이 있는 설문은 응답자가 Google 계정으로 로그인해야 하고 올린 파일이 저장소 주인의 Drive에 쌓인다. 로그인 없이 쓰는 창구로 두려고, 이미지는 설문 설명에서 `pblsketch@gmail.com` 으로 메일을 보내 달라고 안내한다(주소가 공개되는 것은 감수한다).

## 결과

- 설문은 2026-10-18에 저장소 주인 계정(`wnsdlf1212@gmail.com`)으로 만들어 게시했고, 주소를 `apps/shell/src/main/feedback.ts`의 `FEEDBACK_SURVEY_URL`에 넣었다. 설문은 `https://docs.google.com/forms/d/e/1FAIpQLSfD_dlKfi_ZkcjBJFTH3S2nldTIoW0cMI9d_yDaEe6DwKY47A/viewform`이다. 항목을 고쳐도 이 주소는 바뀌지 않으므로, 설문 내용을 다듬어도 앱의 코드를 다시 고칠 필요가 없다.
- 문항은 넷이다. '어떤 점을 알려 주시나요?'(객관식, 필수, 버그 신고·기능 제안·사용 후기·기타), '자세한 내용'(장문형), '앱이 복사해 준 정보 (버전·운영체제·화면 언어)'(단답형), '답변을 받고 싶으시면 이메일을 적어 주세요'(단답형). 응답 수집은 켜져 있고 이메일 주소 수집은 꺼져 있어 로그인 없이 응답할 수 있다.
- 설문 겉모습은 제품과 맞췄다. 머리글 배너는 소개 사이트가 두는 `public/form-banner.png`(생성기 `capture/form-banner.mjs`, 1600×400)를 설문의 헤더 이미지 URL로 넣었고, 테마 색은 제품 인디고 `#4338ca`, 배경은 밝은 `#ecebfa`다. 글꼴은 Google Forms가 주는 기본(Roboto)을 그대로 쓴다(Wanted Sans는 Forms 목록에 없다). 배너를 바꾸면 PNG를 다시 올리고 설문에서도 다시 골라야 한다.
- 새 전송 경로가 하나 생긴다. 사용자가 설문을 열어 무언가 적을 때, 그 내용은 사용자의 브라우저에서 Google로 간다. 앱은 관여하지 않는다.
- 앱은 계속 서버도, 계정도, 사용 통계도 갖지 않는다. 이 창구는 사용자가 직접 누를 때만, 사용자의 브라우저에서 나간다.
- 설문 응답에는 문서 내용이 없으므로, 재현에 문서가 필요하면 답을 받은 뒤에 따로 요청해야 한다.
