# 0049 — 에이전트 창의 웹 사용을 각 회사 앱의 기본값에 맞추고, 두 프로그램에 같은 스킬 목록을 준다

0032를 고친다.

## 맥락

0032의 에이전트 모드에서 Claude Code는 도구 8개로 웹 도구가 없었고, Codex는 격리 안에서 인터넷이 막혀 있었다. 웹 검색은 Codex의 기본값(저장된 결과)을 따랐다.

저장소 주인은 "Claude도 Codex도 각 회사 앱의 기준에 맞추자, 굳이 더 보수적으로 할 필요가 없다"고 정했다(2026-10-21). 일반 AI 창의 "앱이 끌 수 있는 도구는 모두 끈다" 규칙은 검토한 뒤 유지하기로 했다. 일반 창에는 앱 자체 웹 검색이 Claude·Codex 모두에게 있고 가리기·드라이브 유출 막기를 거친다.

사용자 스킬(0048)을 더하면서, 에이전트 창도 설정의 켜기·끄기를 따라야 했다. Codex는 자기 스킬 폴더를 스스로 읽었다. 그래서 설정과 상관없이 스킬이 실렸고, 내 스킬 폴더(`~/.ieumoffice`, 격리의 거부 경로)는 읽지 못했다.

## 결정

- **Claude Code에 `WebSearch`, `WebFetch`를 켠다(도구 10개).** Claude Code 앱처럼 처음에 묻는다. 웹 검색은 처음 쓸 때, 웹 읽기는 사이트마다 묻고, "이번 세션 동안" 허락은 세션 메모리에만 둔다. "믿고 맡기기"는 지금처럼 `auto` 모드가 판단한다.
- **Codex 웹 검색은 저장된 결과(`cached`)가 기본이다.** 프로젝트 폴더마다 실시간·끄기로 바꾼다. 값은 세션 전용 프로그램의 설정 덮어쓰기 맨 뒤에 붙인다. 일반 창의 `web_search="disabled"`보다 뒤에 와서 이긴다(2026-10-21 `config/read`로 확인).
- **Codex 명령의 인터넷 접속은 기본 꺼짐이고, 프로젝트 폴더마다 켤 수 있다.** 켜면 세션 권한 프로필의 `network.enabled = true`로 연다. 사이트 목록은 두지 않는다(Codex 앱의 켜기와 같다). 켤 때 경고를 보인다. 2026-10-21 이 PC(codex-cli 0.159.2)에서 MXC 격리로 확인했다. 끈 상태는 주소 해석부터 실패했고, 켠 상태는 바깥 주소에 닿았다. 두 경우 모두 거부 폴더는 읽히지 않았다.
- **설정은 프로젝트 폴더마다 기억한다.** 남에게 받은 다른 폴더에 켜 둔 설정이 따라가지 않게 하려는 것이다. 저장소 주인이 골랐다.
- **두 프로그램이 같은 스킬 목록을 받는다.** 켜진 스킬과 프로젝트 스킬을 앱이 묶음으로 복사한다. Claude는 플러그인으로, Codex는 스스로의 스킬 찾기를 끄고(`skills.include_instructions=false`) 읽기 경로와 지시문의 목록으로 받는다. 프로젝트 폴더의 스킬은 Claude Code·Codex 앱처럼 묻지 않고 켠다. 저장소 주인이 골랐다.
- **세션 MCP 서버에 `propose_skill`, `propose_skill_install`을 더한다(13개).** 둘 다 창에 카드와 미리보기를 띄우기만 하고, 저장·설치는 사람이 누른다. 시작 확인은 앱 서버 도구를 이름까지 본다.

## 택하지 않은 것

- **Codex 인터넷을 정한 사이트만 허용.** 처음 제안했으나 저장소 주인이 Codex 앱 기준을 골랐다.
- **일반 창에서도 Codex 자체 웹 검색을 켠다.** 얻는 것이 거의 없고, 앱이 볼 수 없는 길이 생기며, Codex에서만 동작이 달라진다. 일반 창은 이 결정과 따로 낸 수정으로 끈다(`web_search="disabled"`).
- **Codex가 자기 스킬 폴더를 읽게 둔다.** 설정의 켜기·끄기를 따르지 않고, 내 스킬 폴더를 읽지 못한다.

## 결과

- 명령 인터넷을 켜고 "믿고 맡기기"를 고르면 Codex의 명령이 묻지 않고 인터넷에 닿는다. 받은 문서에 숨은 지시가 자료를 밖으로 보낼 수 있다. 켤 때의 경고가 이를 알린다.
- 스킬 묶음 폴더는 모든 세션이 같이 쓴다. 도는 세션이 있는 동안 다른 세션을 시작하면 사본이 바뀔 수 있다.
