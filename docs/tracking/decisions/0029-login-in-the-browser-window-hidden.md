# 0029 — 구독 로그인은 창을 숨기고 브라우저에서 하며, 코드가 필요할 때만 창을 보인다

## 맥락

로그인 버튼과 "다른 계정으로 로그인"은 프로그램 자신의 로그인 명령(`claude auth login`, `codex login`)을 새 콘솔 창에서 실행했다. 창에는 영어 안내와 긴 주소, "Paste code here if prompted >"가 뜬다. 저장소 주인이 설치본으로 확인하다가 터미널에 익숙하지 않은 사람에게는 어렵다고 했다.

보통의 로그인은 브라우저에서 끝난다. 프로그램이 브라우저를 열고, 사용자가 그 회사의 페이지에서 로그인하고 허용하면 프로그램이 로그인을 받아 가고 창은 저절로 닫힌다. 창이 꼭 필요한 것은 브라우저가 프로그램과 이어지지 못해 코드를 보여 주고, 그 코드를 창에 붙여 넣어야 할 때뿐이다.

로그인은 그 회사의 프로그램과 웹 페이지가 해야 한다. 앱은 로그인 화면을 만들지 않고, 로그인 정보나 코드를 받거나 전달하지 않는다(Anthropic의 Claude Code 이용 조건도 로그인이 Anthropic의 흐름 안에서 끝나야 하고, 앱이 로그인 정보를 중계하지 않아야 한다고 정한다).

## 결정

- 로그인 버튼은 같은 명령을 콘솔을 숨긴 채 실행한다(`Start-Process -WindowStyle Hidden`). 프로그램은 진짜 콘솔을 가지고 그대로 돌며, 브라우저를 스스로 연다.
- 그동안 카드는 "로그인하는 중"이 되어 열린 브라우저에서 로그인하라고 안내한다. 상태의 `signingIn`(`browser`)이 이 표시이고, 모든 편집기와 설정의 카드가 같은 값을 본다.
- 카드의 링크("브라우저가 안 열리거나 코드가 나오나요?")는 로그인을 다시 부른다. 숨긴 로그인이 도는 중이면 그것을 끝내고 같은 명령을 보이는 창으로 띄운다(`signingIn: window`). 사용자는 브라우저가 보여 준 코드를 그 창에 직접 붙여 넣는다.
- 숨긴 로그인은 10분이 지나면 끝낸다. 끝나면 카드는 다시 로그인 버튼을 보인다.

## 택하지 않은 것

- **창을 그대로 두고 앞에 설명만 더한다.** 가장 안전하지만 검은 창이 그대로 남는다.
- **앱이 코드 입력란을 두고, 받은 코드를 프로그램에 넘긴다.** 앱이 로그인 코드를 다루게 된다. 로그인 정보에 손대지 않는다는 규칙과 회사의 이용 조건에 걸린다.
- **앱이 직접 OAuth 흐름을 연다.** 앱 안의 로그인 화면이고, 회사의 프로그램이 하는 로그인을 바꾸는 일이다.

## 결과

- 대부분의 사용자는 검은 창을 보지 않는다. 코드가 필요한 사람만 링크로 창을 연다.
- 프로그램은 고치지 않는다. 앱은 여전히 로그인 명령을 실행하기만 하고, 코드와 로그인 정보는 보지 않는다.
- 숨긴 창에서 프로그램이 브라우저 로그인을 받아 가는지는 단위 테스트로 확인할 수 없다. 실제 Claude·Codex 계정으로 한 번씩 확인한다.
- 숨긴 로그인이 도는 동안 코드를 기다리면 사용자는 그 사실을 볼 수 없다. 카드의 안내와 링크, 10분 제한으로 다룬다.
