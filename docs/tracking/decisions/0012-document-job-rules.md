# 0012 — 문서 작업은 명시적 행동으로만 시작하고, 대화와 따로 돌며, 스스로 이어 가지 않는다

## 맥락

AI 페이지 읽기와 문서 번역(결정 0010)은 AI 요청을 수십에서 수백 번 보내는 긴 작업이다. 그때까지의 규칙은 "AI 실행은 AI 창에서 요청할 때만 시작한다"였고, 실행 하나는 AI 창의 대화 한 차례에 묶여 있었다. 긴 작업을 대화 안에서 돌리면 그동안 대화를 쓸 수 없다. 분량 상한을 두면 큰 문서를 다룰 수 없고, 두지 않으면 한도에 막혔을 때와 앱이 꺼졌을 때의 처리가 필요하다. 사용자는 페이지 읽기와 번역 모두 상한 없이 "예상 호출 수를 보여 주고 확인받는" 쪽을 골랐다.

## 결정

- **시작.** 사용자의 명시적 행동으로만 시작한다. PDF 편집기의 메뉴 버튼, AI 창의 요청, `--yes`가 붙은 명령, MCP 도구 호출이다. 앱 안에서는 어느 길이든 시작 전 확인(예상 호출 수, 제공자, 요금 경로면 요금 부과 문구)을 거친다. AI 창의 요청은 작업 창을 여는 도구를 부를 뿐이다. 동작 규칙의 "AI 실행은 AI 창에서 요청할 때만"을 "사용자의 명시적 행동(AI 창 요청 또는 문서 작업 버튼)으로만"으로 넓혔다.
- **대화와 따로.** 작업은 AI 대화와 따로 돈다. 작업이 도는 동안에도 대화를 쓸 수 있다. 한 문서에는 작업이 한 번에 하나다.
- **분량 상한 없음.** 페이지 수와 블록 수에 상한을 두지 않는다. 확인에서 예상 호출 수를 보여 준다.
- **한도 소진 때 즉시 멈춤.** `rate-limit`이면 남은 것을 더 보내지 않고 멈추고, 다시 가능한 시각을 보여 준다. 다른 제공자로 넘어가지 않는다. 그 밖의 실행 오류는 한 번 다시 보내고, 3개 잇달아 실패하면 멈춘다.
- **끝난 것은 남긴다.** 결과는 하나 받을 때마다 보관소에 쓰고, 보관된 것만 끝난 것으로 센다. 보관은 사용자가 지울 때까지다.
- **스스로 이어 가지 않음.** 작업은 탭에 묶여 탭을 닫거나 앱이 끝나면 멈춘다. 다시 켜도, 한도가 풀려도 저절로 시작하지 않는다. 다음에 그 문서를 열면 이어 할지를 한 번 묻고, 고르면 다시 시작 전 확인을 연다.
- 번역이 멈추면 끝난 부분만 반영한 파일을 내보낼지, 나중에 이어 할지를 사용자가 고른다.

## 택하지 않은 것

- **AI 창의 대화 한 차례 안에서 돌린다.** 슬라이드 생성(`generate_deck`)이 이 방식이다. 작업 내내 대화를 쓸 수 없고, 그 경로는 한도 소진 뒤에도 계속 시도하는 문제가 있다.
- **한 번에 보낼 분량에 상한을 둔다.** 큰 문서를 여러 번 나눠 시작해야 한다. 사용자가 고르지 않았다.
- **앱을 다시 켜면 끝나지 않은 작업을 자동으로 이어 간다.** 사용자가 모르는 사이 구독 한도를 쓴다. "AI 호출은 명시적 행동으로만"에 어긋난다.
- **한도가 풀리면 기다렸다가 이어 간다.** 같은 이유로 택하지 않았다.

## 결과

- 보관소(데이터 폴더의 `pdf-store`)와 작업 기록, 다시 열 때의 제안, 앱 안 저장 뒤의 보관분 옮기기가 필요하다. 보관소에는 문서 내용이 PC에 남으므로 개인정보 문서와 설정의 지우기 버튼이 따른다.
- 같은 문서를 앱과 터미널이 동시에 다룰 수 있어 보관소는 항목 단위로 원자적으로 쓴다.
- `generate_deck`의 한도 소진 뒤 계속 시도하는 문제는 이번에 고치지 않았다. 새 작업 엔진에는 그 문제가 없다.
