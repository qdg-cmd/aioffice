# 0014 — 마인드맵 파일은 직접 만든 엔진으로 열고 저장하고, 편집 화면의 결과를 원본 나무에 맞춘다

## 맥락

마인드맵 편집기를 넣으면서 약속한 것은 "XMind 파일(.xmind)을 열고 고쳐서 같은 파일로 저장하고, 이 편집기가 다루지 않는 요소도 잃지 않는다"이다. XMind 파일에는 이 편집기가 보여 주지 않는 것이 많다(경계, 떠 있는 토픽, 말풍선, 요약 아래 가지, 다른 토픽·첨부로 가는 링크, 시트 스타일, 확장 정보, 모르는 키).

편집 화면 라이브러리 후보는 mind-elixir와 simple-mind-map이었다. 둘 다 XMind 가져오기·내보내기를 갖고 있지만, 파일을 자기 자료 모양으로 바꿨다가 새로 써내기 때문에 자기가 모르는 요소는 사라진다. 또 라이브러리 안에서 일어나는 편집(되돌리기, 여러 개 한꺼번에 옮기기, 붙여 넣기)은 동작 단위로 빠짐없이 따라가기 어렵다.

## 결정

- `.xmind` 읽기·쓰기는 이 프로젝트의 패키지 `packages/xmind-engine`이 한다. 열 때 zip 안의 모든 항목을 원본 바이트로 기억하고 `content.json`은 원본 나무로 통째로 든다. 편집 화면에는 보기용 자료만 준다.
- 화면의 개별 동작을 번역하지 않는다. 화면의 결과 상태를 받아 토픽 식별자로 짝을 짓고, 편집기가 다루는 값 가운데 실제로 달라진 것만 원본 나무에 적는다(`reconcileSheet`). 어긋나면 원본 나무가 이기고 화면을 다시 그린다.
- 바뀐 것이 없는 저장은 원본과 바이트까지 같다. 바뀌었으면 `content.json`만 다시 쓰고 다른 항목은 원본 바이트로 옮긴다.
- `ok`로 열리지 않은 파일(예전 형식, 암호, 읽을 수 없음, zip 안전 검사 거절)은 문서가 되지 않고, 어떤 저장 길로도 쓰지 않는다.
- 편집 화면은 mind-elixir이고 `5.15.1`로 정확히 고정한다. 시트마다 인스턴스를 따로 두어 되돌리기 기록이 섞이지 않게 한다.
- 이 약속을 지키려고 정한 편집 규칙:
  - 요약과 경계는 순번이 아니라 감싸던 토픽을 따라간다. 감싸던 토픽이 모두 지워질 때만 지운다.
  - 같은 시트에서 잘라 내 붙이면 원본 토픽을 통째로 되넣는 옮기기다(식별자, 모르는 키, 보이지 않는 가지까지).
  - 보이지 않는 요소가 함께 지워지는 토픽 삭제는 사람에게 개수를 알리고 확인을 받는다. AI는 그런 토픽을 지우지 못한다(실행 중에 확인을 받을 수 없다).
  - 시트 삭제는 되돌리기 기록이 시트마다 따로라 Ctrl+Z로 살릴 수 없으므로, 되돌릴 수 없다는 확인 창을 먼저 띄운다. 마지막 시트는 지울 수 없다.

## 택하지 않은 것

- **라이브러리의 XMind 가져오기·내보내기.** 모르는 요소가 사라진다. "잃지 않는다"는 약속은 파일 쪽을 직접 쥐어야 지킬 수 있다.
- **화면의 동작을 하나하나 번역해 원본 나무에 적기.** 라이브러리 안에서 일어나는 일을 빠짐없이 따라가지 못하면 그만큼 파일이 어긋난다. 결과만 보면 빠질 것이 없다.
- **simple-mind-map.** 제작자가 손을 뗐고 의존성이 14개다. mind-elixir는 관리되고, 의존성이 없고, 색을 CSS 변수로 받아 색 토큰 규칙과 맞는다. 사용자가 골랐다.
- **버전 범위 지정.** npm의 `latest` 꼬리표가 시험판(6.0)을 가리킨다.
- **시트 작업까지 되돌리기에 넣기, 보이지 않는 요소를 말없이 지우기.** 사용자가 보지 못한 내용이 말없이 사라진다.

## 결과

- 파일 형식을 우리 코드가 정하므로, 라이브러리를 바꿔도 파일 호환은 그대로다. 대신 형식 처리의 책임이 이 프로젝트에 있다.
- 맞추기가 결과만 보기 때문에, 지운 토픽을 되돌릴 때 화면 상태만으로는 그 토픽이 지녔던 보이지 않는 것을 살릴 수 없다. 편집기가 되돌리기 단계마다 시트 원본 나무의 사본을 둔다.
- 바뀐 저장에서 `content.json`은 플랫폼의 JSON으로 다시 쓰인다. XMind가 만든 파일은 글자 그대로 돌아오지만, 다른 프로그램이 만든 파일은 달라질 수 있다(풀리지 않은 문제에 적었다).
- mind-elixir를 올릴 때는 버전을 직접 바꾸고, 요약·연결선을 스스로 잊는 동작과 글을 `innerHTML`로 넣는 자리를 다시 확인해야 한다.
