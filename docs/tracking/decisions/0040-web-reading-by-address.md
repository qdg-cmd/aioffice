# 0040 — 링크의 본문을 AI가 읽는다: 공개 페이지는 그대로, 비공개 GitHub은 설정의 토큰으로

## 맥락

편집기의 AI 창은 웹의 글을 검색 결과의 제목·주소·한 줄 발췌로만 봤다(`web_search`). 그래서 사용자가 링크로 준 스킬 문서(`SKILL.md`)나 글을 읽으라고 하면 본문을 못 읽고 발췌 수준에서 답했다. 스킬을 AI 창에 싣는 경로 자체가 없다는 것도 함께 드러났다(스킬은 에이전트 모드 전용). Aside 브라우저의 AI 패널과 견준 결과 "웹 문서 본문 읽기"가 1순위로 가져올 것이었다.

사용자가 정한 것: 여덟 편집기 모두(웹 검색이 없는 PDF·한글 포함), 한도는 넉넉하게, 터미널·MCP에도 노출, 스킬 문서는 공개·비공개 GitHub 저장소 모두에서 사용, 예전 인코딩(EUC-KR·CP949)을 쓰는 한국 웹페이지의 글자가 깨지지 않게.

## 결정

- **여덟 편집기 AI 창에 `read_url` 도구.** 웹 검색 유무와 무관하게 항상 도구 목록에 있다. 터미널은 `ieumoffice read-url <url> [--offset <n>]`, MCP는 `read_url`. 결과와 실패 이유(종료 코드·`error`·`detail.errorCode`)는 공개 계약으로 `docs/contracts.md`에 적는다.
- **글 페이지만** 받는다(`text/*`, JSON, XML). 그림·PDF·오피스 파일은 "파일로 내려받아 첨부하라"고 안내한다 — 링크로 받은 파일의 본문 파싱은 이번 범위가 아니다.
- **받기는 앱의 기존 가드로.** `fetchWithSsrfGuard`의 홉별 사설·루프백 검사를 그대로 쓰고, 내려받기 10MB·요청 30초(연결·리다이렉트·본문 전부)·리다이렉트 10회. 글은 50,000자씩 나눠 주고 `offset`으로 이어 읽는다(도구 결과가 다음 턴마다 제공자에게 다시 전송되기 때문). 같은 주소 재읽기는 뒷단 메모리에서 3분·최근 8개까지 재사용한다. 인코딩은 사이트가 선언한 것(Content-Type charset → HTML meta → UTF-8)을 따른다.
- **비공개 GitHub은 사용자가 설정에 넣은 읽기 전용 토큰으로만.** 토큰은 `ai-settings.json`에 평문으로 저장한다(AI 제공자 키와 같은 방식 — 터미널·MCP가 Electron 없이 같은 파일을 읽어야 한다). 토큰은 `api.github.com` 요청에만 실리고, 다른 사이트·리다이렉트 홉에는 싣지 않는다. 로그인 화면·쿠키·브라우저 기록에는 관여하지 않는다. 그 밖의 로그인 벽은 지원하지 않고 파일 첨부를 권한다.
- **요금 경로와 무관.** 제공자·구독·가용성 보고·자동 호출 장부를 쓰지 않는다. 드라이브에서 읽은 내용이 대화에 들어온 뒤 밖으로 나가는 호출을 막는 목록(`OUTBOUND_TOOLS`)에 `read_url`을 더한다.
- 화면 카드·도움말(`google-drive`·`ai-models`·`cli`)·설정 문구는 21개 언어. 스킬 문서의 상대 링크(`references/…`)는 문서 주소 기준으로 풀어 읽으라는 안내를 도구 설명·프롬프트에 담는다.

## 택하지 않은 것

- **링크로 받은 PDF·한글·오피스 파일 본문 읽기.** 파일 해석·보안·크기 상한이 늘고, 첨부 읽기(`read_attachment`)가 이미 그 일을 한다.
- **사이트별 자격 증명(사내 위키 등).** 로그인에 관여하지 않는다는 원칙과 부딪힌다. 사이트마다 토큰을 받는 창을 새로 설계해야 한다.
- **브라우저 쿠키·방문 기록 읽기.** 어떤 경우에도 — 이 앱은 브라우저가 아니다.
- **자체 서버를 거쳐 본문 받기.** 서버·계정 없는 앱 원칙.
- **실패 카드의 코드 9종별 문구 매트릭스.** 기존 도구처럼 번역된 한 줄 요약을 쓰고, `errorCode`는 데이터에 남긴다.

## 결과

- 코드는 `packages/ai-search`(도구 본체 `src/read-url.ts`·HTML→글 `src/html-text.ts`, parse5 의존성), `packages/electron-utils`(가드에 `signal`·`headersForHop`), `packages/ai-provider`(설정 슬롯 `readUrl.githubToken`), 핸들러 세 곳(껍데기 공용 `apps/docs` + 단독 `slides`·`sheets`), preload 여덟 곳, 편집기 여덟 곳의 도구 정의·프롬프트·문구(21개 언어), `packages/cli`(명령·MCP 도구·README·스킬), 설정 화면(`apps/shell`)에 있다.
- 이 PC(Windows)에서 패키지별 검사와 합치기 전 검사 목록을 통과했다(기준: 손대지 않은 원본에서도 실패하는 Windows 사례 제외 — 그 목록은 `docs/tracking/findings.md`의 "Windows에서 원본 코드 그대로도 실패하는 테스트가 있다"와 각 AGENTS 파일에 있다).
- 빌드한 앱에서 링크를 실제로 읽는 확인(공개 스킬 링크, 비공개 저장소 토큰, 거절 사례)은 아직 하지 않았다 — 실행 묶음의 마지막 실제 확인 단계와 릴리스 전 확인으로 남긴다.
