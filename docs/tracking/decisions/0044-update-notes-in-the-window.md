# 0044 — 업데이트 창에 릴리스 본문을 보여 준다

## 맥락

업데이트 창은 "새 버전이 있습니다"와 버전 번호만 보여 주었다. 무엇이 바뀌었는지는 GitHub 릴리스 페이지에 가야 알 수 있었고, `docs/releasing.ko.md`에도 "설명은 웹 페이지에만 보입니다"라고 적혀 있었다.

그런데 `electron-updater`는 업데이트를 확인할 때 릴리스 본문을 이미 받아 온다. GitHub provider가 `releases.atom`을 먼저 요청하고, 그 응답의 `<content>`에 GitHub가 렌더링한 본문(HTML)이 들어 있다. 앱이 그 값을 쓰지 않았을 뿐이다. `fullChangelog`를 켜면 같은 응답 하나로 "지금 쓰는 버전 이후"의 본문 전부를 받는다.

## 결정

**창에서 바뀐 점을 읽게 한다.** 새 네트워크 요청이나 새 창 없이, 이미 받아 오는 본문을 업데이트 창 안에 보여 준다.

- **건너뛴 버전도 보여 준다.** `autoUpdater.fullChangelog = true`. 여러 버전을 건너뛴 사용자는 그 사이 릴리스의 본문을 새 버전부터 역순으로 본다. 피드에 실리는 릴리스 수에는 상한이 있어(약 10개) 있는 것까지만 보인다.
- **본문이 있으면 일반 문구를 숨긴다.** "이 업데이트에는 성능 개선과 버그 수정이 포함되어 있습니다…"는 본문이 없을 때만 쓴다. 실패·수동 안내 문구는 본문이 있어도 그대로 보여 준다.
- **원격 글은 HTML로 화면에 들어가지 않는다.** main의 `update-notes.ts`(parse5)가 GitHub의 HTML을 제목·문단·목록·굵게·고정폭의 블록으로 바꾼다. 링크 주소·그림·스크립트·스타일은 버리고, 화면은 `createElement`/`textContent`로만 조립한다. 원문 256KB·결과 48,000자·섹션 12개의 상한을 둔다.
- **본문은 쓴 언어 그대로 보여 준다.** 앱은 번역하지 않는다. 화면 문구 3개(라벨·GitHub 링크·잘림 안내)만 21개 언어로 옮긴다.
- **창은 내용이 있을 때 커진다.** 400×430 → 400×620. 내용 상자는 최대 200px, 길면 스크롤. 글자는 13px·줄 간격 1.7·왼쪽 정렬, 선택 가능. 짧은 본문이면 상자가 줄어든다.
- **링크는 바닥의 "GitHub에서 전체 보기" 하나.** 기존 `onOpenDownload`(저장소 상수 URL)를 쓴다. 본문 안의 링크는 글자만 남긴다.
- **릴리스 본문 쓰는 절차에 윤문을 넣는다.** 이 글은 사용자가 앱에서 그대로 읽으므로, 초안을 쓴 뒤 humanize-korean 스킬로 윤문한다(`docs/releasing.ko.md`).

## 택하지 않은 것

- **GitHub API로 Markdown 원문 받기.** 새 네트워크 경로가 생기고 익명 호출 제한(시간당 60회)을 받는다. 이미 받아 오는 피드로 충분하다.
- **renderer에서 DOMParser.** 원격 HTML을 렌더러로 넘기게 되고, node 환경 테스트가 어려워진다.
- **본문에서 "설치" 절을 잘라내기.** 절 제목 규약에 의존해 릴리스마다 흔들린다. 대신 본문 쓰는 규약으로 설치 안내를 맨 아래로 옮긴다.
- **접었다 펴는 토글.** 기본 표시보다 발견성이 낮다.
- **본문을 plain text 한 덩어리로.** 굵게·목록이 뭉개져 읽기 나쁘다.

## 결과

- 계획과 화면 설계: `docs/plans/update-details.md`.
- 새 모듈 `apps/shell/src/main/update-notes.ts`(순수 함수, parse5). 셸 의존성에 `parse5` 한 줄이 늘었다(이미 워크스페이스가 쓰던 패키지).
- 테스트: `tests/update-notes.test.ts`(실물 v0.12.1 본문 픽스처, 상한·안전 규칙), `tests/updater.test.ts`(fullChangelog·상태 배선), `tests/update-window.test.ts`(창 높이).
- `docs/releasing.ko.md`의 "설명은 웹 페이지에만 보입니다"를 고치고, 본문 쓰는 순서와 윤문 단계를 적었다.
- 개인정보: 새 전송 경로가 없다. 본문은 창 상태에만 살고 저장·전송되지 않는다(`PRIVACY.md` 무변경).
- 실제 릴리스로 창을 띄우는 확인은 아직이다. `GENOFFICE_FAKE_UPDATE`로 화면을 볼 수 있고, `docs/releasing.ko.md` 8번(베타 프리릴리스)으로 실물 확인한다.
