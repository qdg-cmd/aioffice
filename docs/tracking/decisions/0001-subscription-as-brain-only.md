# 0001 — 구독 프로그램은 한 차례의 답만 내고, 문서는 앱이 고친다

## 맥락

Claude Code와 Codex는 스스로 파일을 읽고 고치고 명령을 실행하는 프로그램이다. 이 앱에 붙일 때, 그 프로그램에게 문서 파일을 직접 고치게 할 수도 있었다. 한편 앱에는 이미 "모델에게 묻기 → 앱이 도구 실행 → 결과 돌려주기"의 반복이 있고, 변경 내용 표시와 AI 차례마다의 되돌리기가 그 도구 실행에 묶여 있다. 원본의 Codex 연동도 같은 구조였다.

## 결정

구독 프로그램은 모델의 답 한 차례만 돌려주는 뒷단으로 쓴다. 프로그램 자신의 도구는 끌 수 있는 것을 전부 끈다(Claude는 0개가 될 때만 실행한다. Codex의 셸 도구는 끌 수 없어 읽기 전용으로 가둔다). 문서 읽기·고치기, 검색, 이미지 생성은 앱이 정의한 도구로만 하고 앱이 실행한다.

## 택하지 않은 것

- **프로그램이 문서 파일을 직접 고치게 한다.** 열려 있는 편집기의 상태와 디스크의 파일이 어긋나고, 변경 내용 표시와 되돌리기를 거치지 않는다. 프로그램에 파일·명령 권한을 줘야 해서 사용자 PC 전체가 위험 범위에 들어간다.
- **앱의 도구를 MCP 서버로 내놓고 프로그램이 직접 부르게 한다.** 반복의 주도권이 프로그램으로 넘어가 중단·되돌리기 지점·사용량 표시를 앱이 통제하지 못한다. 프로그램에 MCP 연결을 허용해야 해서 "도구 0개" 검사를 할 수 없다.

## 결과

- 차례마다 프로그램을 새로 띄우므로(Claude) 답의 시작이 몇 초 늦다.
- 대화 전체를 매 차례 다시 보낸다. 긴 대화일수록 입력이 커진다.
- 모델이 받은 대화가 사용자 글 한 덩어리라, 이미 실행된 도구 호출을 다시 요청하지 않도록 안내 글을 붙여야 한다.
- 프로그램이 가진 기능(자체 파일 도구, 웹 검색, 하위 에이전트)은 이 앱에서 쓰지 못한다.
