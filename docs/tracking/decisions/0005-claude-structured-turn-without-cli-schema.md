# 0005 — Claude의 도구 호출은 지시문으로 받은 구조화 응답으로 받고, 프로그램의 스키마 옵션은 쓰지 않는다

## 맥락

앱의 반복은 모델에게서 "글 + 도구 호출 목록"을 받아야 한다. Claude Code는 자기 도구를 끈 상태에서는 앱의 도구를 직접 부를 수 없으므로, 도구 호출을 구조화된 답으로 흉내 내야 한다. Claude Code에는 답의 구조를 강제하는 옵션(`--json-schema`)이 있다. 한편 이 앱은 "프로그램이 보고한 도구가 0개일 때만 실행한다"는 규칙을 둔다. 내장 도구를 꺼도 사용자 설정의 MCP 연결이 딸려 오는 것을 실제로 봤기 때문이다.

## 결정

응답 구조는 지시문과 대화 앞머리에 적어 주고, 돌아온 답을 앱이 검사한다. 프로그램의 스키마 옵션은 쓰지 않는다. 구조에 맞지 않는 답과 목록에 없는 도구 호출은 반복의 기존 재시도 흐름에 오류로 돌려준다.

## 택하지 않은 것

- **`--json-schema`로 구조를 강제한다.** 이 옵션은 프로그램에 `StructuredOutput`이라는 도구를 하나 더한다. 그러면 도구 목록이 비지 않아 0개 규칙과 부딪힌다. 그 도구 하나만 예외로 두면 "목록이 비었는가"라는 단순한 검사가 "허용된 이름만 있는가"로 바뀌고, 프로그램이 이름을 바꾸면 깨진다.
- **끄는 옵션을 믿고 검사를 뺀다.** 실제로 도구가 딸려 왔다.

## 결과

- 모델이 구조를 어길 수 있다. 코드 울타리로 감싼 답은 벗겨서 읽고, 그래도 안 맞으면 재시도한다.
- 구조가 프로그램 수준에서 보장되지 않으므로 도구 호출 수와 크기의 상한을 앱이 직접 건다.
- 도구 0개 검사는 "목록이 비었는가" 하나로 남는다.
