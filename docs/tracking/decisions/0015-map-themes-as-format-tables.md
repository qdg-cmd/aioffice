# 0015 — 지도 테마는 파일 형식의 속성표로 적고 그 표로 다시 알아본다. 지도의 색은 문서 내용이다

## 맥락

사용자는 편집 화면 라이브러리의 기본 모양보다 나은 지도를 원했다. 직접 만든 테마(뼈대 4 × 색 띠 8 × 바탕 3 = 96가지)를 고를 수 있게 하면서, 두 가지가 걸렸다. 고른 테마가 파일에 남아 다른 프로그램에서도 비슷하게 보이고 이 앱에서 다시 열어도 같은 모양이어야 한다. 그리고 문서 안에 이 앱만의 것을 넣지 않는다는 규칙(`docs/standards.md`)이 있다.

XMind 파일의 테마는 단계마다(`map`, `centralTopic`, `mainTopic`, `subTopic`) 속성표를 가진다. 지도 파일은 남에게서 받는 일이 많아, 파일 안의 값이 화면의 스타일·그림 주소·화면 요소가 되는 길도 막아야 했다.

## 결정

- 사용자가 테마를 고르면 그 시트의 테마를 파일 형식의 속성표로 적는다. 고르지 않으면 파일의 테마를 건드리지 않는다.
- 다시 열 때는 그 속성표를 이 앱이 적는 표와 속성 하나하나까지 견주어 알아본다(`recogniseTheme`). 이 앱만의 표식을 파일에 넣지 않는다.
- 한 번 배포한 판이 적은 표는 값을 바꾼 뒤에도 계속 알아본다. 값을 바꾸기 전에 마지막 배포판의 표를 `SHIPPED_THEME_TABLES`에 옮긴다.
- 이 앱이 적지 않은 테마(XMind에서 온 파일, 다른 프로그램이 다시 저장해 속성이 달라진 표)는 알아보지 않는다. 그 시트는 기본 모양으로 그리고 파일의 테마는 그대로 두며, 열 때 그렇다고 알린다. XMind의 테마를 읽어 비슷하게 그리는 일은 다음으로 미룬다.
- 지도의 색은 문서 내용이다. 화면 틀 토큰을 참조하지 않고, 앱의 밝게·어둡게를 따라가지 않는다. 그림·PDF·인쇄·미리보기 그림의 결과는 두 테마에서 같다. 화면 틀(도구 줄, 탭, 패널)은 앱의 테마를 따르고 지도의 밝기를 따라가지 않는다. "밝은 앱 + 어두운 지도"가 나올 수 있다.
- 파일 안의 값을 믿지 않는다. 토픽 스타일은 색 꼴(`#` 16진)과 숫자 꼴만 이 앱이 다시 써낸 값으로 화면에 들어간다. 그림은 파일 안의 것만 보인다. 링크는 `safeExternalUrl`을 거친 것만 열린다. 제목과 글은 HTML로 해석하지 않는다.
- 색 띠의 값과 이름, 뼈대, 표식 그림은 모두 직접 만든다. 파일 형식의 속성 이름과 식별자를 읽고 쓰는 것은 호환이다.

## 택하지 않은 것

- **파일에 앱 전용 표식 넣기.** 문서 안에 저장되는 것을 늘리지 않는다는 규칙에 걸린다.
- **테마는 보존만.** 고른 모양이 파일에 남지 않아 다른 프로그램에서 열면 사라진다.
- **지금 값의 표만 알아보기.** 테마의 색이나 수치를 다듬을 때마다 예전에 저장한 지도가 기본 모양으로 돌아간다.
- **화면 틀이 지도의 밝기를 따라가기.** 화면 색은 토큰으로만, 문서 색은 테마와 무관하게라는 기존 규칙과 어긋난다.
- **파일의 스타일 값을 그대로 쓰기.** 남이 만든 파일의 글자가 화면의 스타일이나 바깥 주소가 된다.

## 결과

- 테마의 값을 바꾸는 사람은 배포 여부를 확인하고 표를 옮겨야 한다. 지금 적는 표를 고정한 테스트(`packages/xmind-engine/tests/theme-table.test.ts`)가 값이 바뀌면 실패해서 이 일을 알린다. 아직 배포한 판이 없어 목록은 비어 있다. (2026-10-21 덧붙임: 0.12 판이 배포되어, 그 판이 적은 표를 0045에서 `SHIPPED_THEME_TABLES`로 옮겼다.)
- XMind에서 다시 저장한 지도는 이 앱에서 기본 모양으로 보인다.
- 지도 쪽 CSS와 그리는 코드에는 색 값이 없고, 색은 모두 엔진의 테마 자료에서 온다.
