# 0004 — 터미널·MCP 요청의 구독 사용은 기본 꺼짐, 켜도 제한을 둔다

> **대체됨 → [0011](0011-no-hourly-cap-on-automatic-calls.md)** (2026-10-14). 기본 꺼짐 스위치, 경고, 한 번에 하나는 남았다. 시간당 20건 한도는 없어졌다. 아래는 그때의 기록이다.

## 맥락

터미널 명령어와 MCP로 들어오는 요청은 다른 프로그램(코딩 에이전트 등)이 보낸다. 화면을 보는 사람이 없다. Anthropic은 구독 로그인이 통상적인 개인 사용을 전제한다고 하고, OpenAI는 프로그램적 사용에는 API 키를 쓰라고 한다. 어기면 제한을 받는 것은 사용자의 계정이다. 사용자는 이 경로에서도 구독을 쓰고 싶어 했다.

## 결정

- 이 경로에서 구독을 쓰는 것은 설정 스위치로 켠다. 기본은 꺼짐이고, 켤 때 계정 제한 위험을 알리는 경고를 보여 준다.
- 켜져 있어도 한 번에 하나씩, 한 시간에 20건까지만 처리한다. 횟수는 따로 실행된 프로세스들에 걸쳐 합산한다. 장부를 읽을 수 없으면 막힌 것으로 본다.

## 택하지 않은 것

- **이 경로에서 구독을 아예 못 쓰게 한다.** 가장 안전하지만, 위험을 알고도 쓰려는 사용자의 선택을 막는다.
- **화면 경로와 똑같이 허용한다.** 에이전트가 반복 호출하면 사용자가 모르는 사이 한도를 다 쓰고, 계정이 제한될 수 있다.
- **제한 없이 스위치만 둔다.** 켠 뒤의 폭주를 막을 것이 없다.

## 결과

- 스위치를 켜지 않은 사용자의 에이전트는 이미지 분석 같은 기능에서 "쓸 수 없음"을 받는다. 그 답에 스위치의 위치가 들어 있다.
- 시간당 한도를 넘으면 정당한 요청도 거절된다.
- 프로세스들 사이에서 횟수를 세기 위한 장부 파일과 잠금 파일을 관리해야 한다.
