# 0039 — 슬라이드 메모(댓글)를 사람과 AI가 읽는다

## 맥락

슬라이드에는 발표자 노트와 별개로 검토 메모(클래식 댓글)가 있다. 앱은 메모 창에서 현재 페이지의 메모만 보여 주고, AI는 메모를 쓸 수는 있었지만 읽지 못했다. 그래서 "모든 메모를 한 번에 보고, AI가 확인"하는 일이 안 됐다. 다른 편집기(워드 댓글·PDF 주석·시트 노트/메모)는 이미 읽기 표면을 갖고 있었다. 처음 질문에서 말한 '메모'는 이 메모 창(댓글)이었다.

## 결정

- **메모 창에 모든 페이지 보기를 더한다.** 페이지 순서로 메모가 있는 페이지만 묶어 보여 주고, 누르면 그 페이지로 이동한다. 보기 전용이며 추가·삭제는 지금처럼 페이지 보기에서 한다. 숨김 슬라이드도 포함한다. 다른 화면(분할 보기의 사본)이나 앱 MCP가 덱을 바꾸면 목록과 리본 배지를 다시 읽는다.
- **앱 AI가 메모를 읽는다.** 새 도구 `read_comments`가 페이지·숨김 표시·식별자(`authorId:idx`)·작성자·시각·본문을 낸다. 덱에 메모가 있으면 문맥에 "메모 N개(페이지 목록)" 한 줄을 넣어 AI가 도구를 부르게 한다. 전문을 매번 문맥에 넣지 않는다(긴 메모의 비용).
- **읽기 표면을 넓힌다**: 앱 안 MCP `read_deck`(열린 문서, `hidden`·`comments`), 터미널 `slides read --comments`(저장본), pptx 첨부 읽기(`### Comments` 블록). 앱 MCP·터미널의 식별자는 기존 `apply_ops deleteComment`가 그대로 받는다.
- **메모는 원문으로 읽는다.** 새 가림·마스킹을 넣지 않는다(워드 댓글·PDF 주석과 같은 기준). 메모는 가리기 표식의 대상이 아니다.
- **삭제는 허용한다.** AI가 읽은 식별자로 지울 수 있고, 사용자가 지워 달라고 할 때만 지운다.
- **첨부에도 메모를 넣는다.** 다른 형식의 댓글은 첨부에서 빠지지만, 슬라이드 메모는 넣기로 정했다.

## 택하지 않은 것

- **발표자 노트(스피커 노트)의 전체 보기·AI 읽기** — 이번 범위가 아니며 다음 작업으로 미룬다.
- **메모 답글·해결 표시** — 클래식 댓글 형식에 없다.
- **메모 자동 요약·번역, 새 마스킹** — 이번 범위 밖이다.
- **터미널에서 열린 세션의 저장 전 메모 읽기** — 터미널은 저장본을 읽는 원래 성질을 지킨다.
- **메모 파트를 읽지 못했을 때 '읽기 실패'와 '메모 없음'을 구분하는 것** — 엔진의 기존 한계(빈 목록)를 유지하고, 첨부는 블록 없이 넘어간다.

## 결과

- 메모 창에서 덱 전체 메모를 훑고 바로 그 페이지로 갈 수 있다.
- 앱 AI·앱 MCP·터미널·첨부가 모두 메모를 읽는다. AI는 필요할 때 도구로 읽고, 지워 달라는 요청에는 기존 삭제 연산을 쓴다.
- 화면 문구는 21개 언어, 도움말 슬라이드 항목에도 한 줄이 들어간다.
