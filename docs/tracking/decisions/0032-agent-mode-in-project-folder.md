# 0032 — 프로젝트 폴더에서 구독 프로그램을 도구를 켠 채 돌리는 에이전트 모드를 더한다

> [0049](0049-agent-web-and-skill-list.md)가 이 결정의 웹 사용과 스킬 싣는 방식을 고친다(2026-10-21). Claude Code는 웹 도구를 켜고, Codex는 스스로의 스킬 찾기를 끄고 앱이 만든 같은 묶음을 받는다.

## 맥락

0001은 구독 프로그램을 "한 차례의 답만 내는 두뇌"로 정했다. 그래서 프로그램이 가진 기능(자체 파일 도구, 명령 실행, 스킬, 하위 에이전트)은 이 앱에서 쓰지 못한다.

문서·슬라이드·마인드맵을 AI로 만들려면 맥락을 다루는 일이 중요하다. 사용자는 두 가지를 원한다. 하나는 로컬 폴더를 프로젝트로 지정해 그 안의 자료를 맥락으로 쓰는 것이다. 다른 하나는 Claude Code·Codex처럼 스킬을 더해 쓰는 것이다. 스킬 안의 스크립트 실행까지 포함한다. 파세오처럼 사용자의 구독 프로그램을 다른 앱 안에서 도구를 켠 채 돌리는 방식이 이미 쓰이고 있다.

이미 있는 것: 별표 그룹(0017, 0020)은 여러 폴더에 흩어진 파일의 묶음이고, 앱이 그 묶음을 읽어 모델에게 건넨다. 앱이 다른 파일을 대신 읽을 때는 가리기가 적용된다(0016). 에이전트에게는 파일 묶음이 아니라 자기 도구로 돌아다닐 작업 폴더가 필요하다.

2026-10-15에 이 PC의 Claude Code 2.1.287로 확인한 것(모델을 부르지 않는 시작 요청만 보냈다):

- `--restricted`를 켜면 `--setting-sources user`를 줘도 사용자 스킬이 실리지 않는다. 기본 명령만 남는다.
- `--restricted`를 끄고 `--setting-sources user`를 주면 사용자 스킬 384개가 실린다. 그런데 모델을 부르기도 전에 사용자 훅 3개가 실행됐다.
- `--restricted`를 켠 채 `--plugin-dir`로 앱이 만든 폴더를 주면, 그 안의 스킬이 실린다. 이때 훅은 실행되지 않는다.
- `--permission-prompts host`와 `--permission-prompt-tool stdio`를 함께 주면 권한 요청이 앱으로 오고, 앱이 허락·거절로 답할 수 있다(haiku로 실제 호출해 확인). 앞의 옵션만 주면 요청이 앱에 오지 않고 "승인 필요"로 끝난다.

## 결정

- 지금의 AI 창(두뇌 방식, 0001)은 그대로 두고 기본으로 남긴다.
- **에이전트 모드**를 더한다. 사용자가 로컬 폴더를 프로젝트로 지정하고 그 프로젝트에서 켤 때만 동작한다. Claude Code와 Codex를 그 폴더를 작업 폴더로 삼아, 자기 도구를 켠 채로 실행한다. 두 제공자를 함께 만든다.
- 열린 문서도 고친다. 단, 열린 문서는 앱 안 MCP 서버의 편집 도구(`apply_ops`, `apply_sheet_ops`, `apply_slide_ops` 등)로만 고친다. 이 도구들은 편집기의 실행기를 그대로 쓰므로 변경 표시와 되돌리기를 거친다. 탭에 열린 파일을 프로그램의 파일 도구로 직접 쓰려는 요청은 거절한다.
- 에이전트 세션이 쓰는 앱 안 MCP의 읽기 도구는 0016과 같은 가리기를 지난다. 처리하지 못하면 읽지 않는다. 지금 이 도구들은 가리기를 지나지 않는다(풀리지 않은 문제 "터미널 명령어와 MCP로 읽을 때는 가리기가 적용되지 않는다"). 바깥 연동의 출력 약속은 이 결정으로 바꾸지 않고, 에이전트 세션의 경로에만 적용한다.
- 허락 방식은 사용자가 고른다. 셋 중 하나다. "명령 실행만 확인"(기본), "쓰기와 실행 모두 확인", "프로젝트마다 한 번 허락".
- PC에 설치된 스킬도 쓴다. 단, 사용자 설정을 통째로 읽게 하지 않는다.
  - Claude: `--restricted`를 유지한다. 앱이 PC의 스킬 폴더만 모은 세션용 플러그인을 만들어 `--plugin-dir`로 준다. 사용자의 훅·MCP 연결·개인 설정은 지금처럼 빠진다.
  - Codex: 스킬 지시문을 켠다(`skills.include_instructions`). 훅·플러그인·앱·메모리는 지금처럼 끈다.
- 그대로 지키는 것:
  - 로그인 정보에 손대지 않는다.
  - 요금이 나가는 연결로 스스로 바꾸지 않는다(0002).
  - 프로그램을 셸 없이 실제 실행 파일로 띄우고, 중단·종료 때 하위 프로세스까지 끝낸다.
  - 원본이 PC에 등록한 것을 건드리지 않는다.

## 택하지 않은 것

- **사용자 설정을 그대로 읽어 스킬을 싣는다**(`--setting-sources user`, `--restricted` 없음). 확인해 보니 모델을 부르기 전에 사용자 훅이 실행됐다. 훅은 임의의 명령이다.
- **에이전트가 열린 문서의 파일을 직접 고친다.** 편집기 화면과 디스크의 파일이 어긋난다. 변경 표시와 되돌리기를 거치지 않는다. 바깥 라이브러리로 저장하면서 문서 안의 식별자(가림 표시 등)를 잃을 수 있다.
- **스크립트를 앱 안의 격리된 공간(WebAssembly Python 등)에서만 실행한다.** 더 안전하지만, 스킬이 기대는 패키지가 돌아가는지가 불확실하다. 사용자가 원하는 "있는 스킬을 그대로 쓰기"에 못 미친다.
- **글로 된 스킬만 받는다.** 스크립트가 든 스킬이 일부만 동작한다.

## 결과

- CLAUDE.md "절대 어기지 않는 것" 3번과 `docs/security.md`의 "프로그램 실행" 절은 이제 "기본 AI 창에서는"으로 좁아진다. 에이전트 모드에서는 명령 실행 도구가 켜진다. 구현과 함께 규칙 문서를 고쳤다(`docs/security.md`의 "에이전트 모드").
- 명령을 가두는 정도가 두 제공자에서 다르다.
  - Codex는 Windows에서도 자체 격리 안에서 명령을 실행한다. 2026-10-15에 이 PC(Windows 11 빌드 26200.9711)에서 `codex sandbox`로 `workspace-write`를 확인했다. 작업 폴더 쓰기는 됐고, 문서 폴더 쓰기는 거부됐고, 인터넷 접속은 막혔다. 에이전트 모드의 Codex는 이 격리를 항상 켠다. 격리를 시작하지 못하면 격리 없이 돌리지 않고 거부한다.
    - 구현하며 확인한 것(2026-10-15): 로그인 폴더 `~/.codex`까지 막으려면 MXC 격리가 필요하고, 읽기도 운영체제 최소 경로로 좁힐 수 있었다. 승인 정책 `on-request`에서는 허락한 명령이 격리 밖에서 돌아서 묻는 방식에는 `untrusted`를 쓴다. 자세한 것은 `docs/security.md`의 "에이전트 모드".
  - Claude Code는 Windows에서 명령을 격리하지 못한다. 공식 문서 기준으로 격리는 macOS·Linux·WSL2만 지원한다. 승인된 명령은 사용자 권한으로 PC 전체와 인터넷에 닿는다. 그래서 Claude의 "프로젝트마다 한 번 허락"은 앱이 모두 허락하는 방식으로 만들지 않는다. Claude Code의 `auto` 모드(별도 모델이 행동마다 검사한다)를 쓴다. `auto`를 쓸 수 없는 계정이면 Claude Code가 수동 확인으로 돌아간다.
  - 받은 문서에 숨은 지시가 명령으로 이어질 위험은 남는다. 에이전트 모드를 켤 때, 그리고 제공자를 고를 때 이 차이를 알린다.
- 가림 보장이 좁아진다. 에이전트는 디스크의 파일을 직접 읽는다. 0016은 앱이 대신 읽는 길에만 적용된다. 워드 문서는 원래 가리기가 닿지 않는다(기존 문제). 그래서 "가린 범위는 어떤 제공자에게도 보내지 않는다"는 앱 도구를 거치는 열린 문서에만 성립한다. 파일 도구로 가림 표시가 있는 파일을 읽는 요청은 거절할 수 있다. 하지만 승인된 명령이 읽는 것은 막지 못한다. 저장소 주인이 이 한계를 받아들였다(2026-10-15). 에이전트 모드를 켤 때 알린다.
- 스킬이 기대는 실행 환경(Python 등)은 사용자 PC에 있어야 한다. 없으면 그 스킬은 실패한다.
- 약관(2026-10-15 조사). 에이전트 모드는 지금의 앱과 같은 약관 조건 위에 있다. 도구를 켜는지 끄는지는 약관의 조건이 아니다.
  - Anthropic: Claude Code 공식 문서의 "Legal and compliance"는 제품 안에서 Claude Code를 실행하는 것을 허용한다. 조건은 넷이다. 상업 약관에 동의한다. 실행 파일을 고치지 않는다. 내장된 로그인 방식을 없애거나 막지 않는다. 사용자 대신 사용료를 내거나 중개하지 않고, 사용자가 자기 구독으로 직접 로그인한다. 첫 번째는 이미 첫 릴리스의 선행 조건이다. 기능 이름이나 로고에 Claude Code·Anthropic 이름을 쓸 수 없고, "Claude Code를 실행한다"는 평문 표현만 된다.
  - Anthropic 사용량: 2026-10-07 갱신된 안내 기준으로, 구독으로 로그인한 `claude -p`는 요금제 사용 한도에서 나간다. 6월 15일로 예고됐던 "프로그래밍 사용은 별도 크레딧, 다 쓰면 켜 둔 경우 추가 요금" 변경은 보류됐다. 이 변경이 되살아나면 지금의 AI 창을 포함한 모든 Claude 사용이 영향을 받는다. 0002(요금 경로)와 함께 다시 본다.
  - OpenAI: Codex는 Apache-2.0이고, `app-server`는 "제품에 Codex를 넣는" 공식 연동 방식으로 문서화돼 있다(승인 요청, 샌드박스 포함). 사용자 구독으로 쓰는 제3자 앱을 명시적으로 금지하는 조항은 찾지 못했다. OpenAI 관리자는 공개 토론에서 약관이 관대하고 비슷한 오픈소스 프로젝트가 있다고 답했다. 다만 사업 용도라면 법률 자문을 권했다. 새 공식 경로인 "Sign in with ChatGPT"는 앱이 로그인 토큰을 다뤄야 해서 이 프로젝트의 규칙 1번과 맞지 않는다. 쓰지 않는다.
  - 다른 앱(파세오)이 같은 방식을 쓴다는 것은 허용의 근거로 삼지 않는다.
- 고칠 문서: CLAUDE.md·AGENTS.md(같은 내용), `docs/security.md`, `docs/architecture.md`, `docs/business-rules.md`, `docs/contracts.md`(설정 파일 값, 앱 안 MCP 서버를 에이전트 모드가 쓰는 방식), `PRIVACY.md`와 첫 연결 안내, 21개 언어 화면 문구.
