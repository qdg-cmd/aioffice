# pptx-render

## 맡은 범위

`pptx-engine`의 슬라이드 모델을 "그릴 준비가 끝난 데이터"(RenderTree)로 바꾼다. EMU→px 좌표와 뷰포트, 채움·선·효과 해석, 글꼴 메트릭 추상화, 텍스트 줄바꿈·줄 간격·자동 맞춤·세로 정렬, 표와 차트의 그리기 원시 요소, 프리셋 도형 경로, 3D 장면이 여기 있다. 진입점은 `buildRenderSlide(slide, size, options)`다. Slides 앱의 Konva 어댑터와 `packages/pipelines`의 레이아웃 점검, 명령줄 도구가 쓴다. 하위 경로 `./preset-geometry`는 `packages/ui`와 Docs가, `./auto-num`은 Sheets가 따로 가져다 쓴다.

## 맡지 않는 것 (경계)

- 실제로 그리지 않는다. Konva 어댑터, 캔버스, 선택 틀·안내선·핸들 같은 편집 표시는 `apps/slides`다. 이 패키지는 DOM, 캔버스, Konva를 import하지 않는다.
- pptx를 읽거나 쓰지 않는다. 상속 풀기와 저장은 `packages/pptx-engine`이다. 렌더 결과를 모델에 되쓰지도 않는다. 슬라이드 번호 필드처럼 표시값만 다른 경우에는 모델의 사본을 만들어 쓴다.
- 편집 연산은 `packages/pptx-ops`다.
- 글꼴 파일을 찾거나 읽지 않는다. 정확한 메트릭이 필요하면 호출자가 opentype.js 글꼴 객체를 넣은 `FontMetricsProvider`를 주입한다. 그림 바이트도 `media`(mediaRef → data URL)로 주입받는다.

## 항상 지켜야 하는 것

- 같은 입력과 같은 메트릭이면 어느 환경에서나 같은 RenderTree가 나와야 한다. 브라우저의 `measureText`에 기대지 않는다. Node 테스트에서 줄바꿈과 좌표를 고정할 수 있는 이유가 이것이다.
- 기하 값은 전부 px이고, 뷰포트 배율과 중첩 그룹의 오프셋·배율이 이미 반영된 절대 좌표다. 정렬(문단 정렬, 세로 맞춤)도 글리프 좌표에 구워 넣는다. 그리는 쪽이 다시 계산할 것을 남기지 않는다.
- 렌더 트리의 색은 문서 데이터다. UI 테마 값을 참조하지 않고, 밝은 테마와 어두운 테마에서 같은 결과를 낸다.
- `pptx-engine`의 기본 진입점에서는 타입만 import한다. 실행 코드가 필요하면 하위 경로(`/table-grid`, `/identity`, `/background-promote`)로 가져온다. 이 패키지는 렌더러 번들에 들어가고, 엔진 기본 진입점은 `node:crypto` 같은 Node 전용 import를 끌고 온다.
- 같은 이유로 엔진의 상수를 가져오지 않고 복사해 둔 값이 있다. `DEFAULT_INSETS_EMU`는 엔진의 `DEFAULT_BODY_INSETS`와 같아야 하고 테스트가 이를 확인한다. 한쪽만 바꾸지 않는다.
- 비정상 입력이 `NaN`으로 번지지 않게 한다. 좌표 변환 함수는 유한수가 아닌 입력에 0을 돌려주고, `makeViewport`는 크기가 0 이하이거나 유한수가 아니면 기본 슬라이드 크기(9144000×6858000 EMU)로, 목표 폭이 비정상이면 배율 1로 떨어진다.
- 프로세스 수명 동안 남는 캐시에는 상한을 둔다. 이미지 DPI 캐시와 이미지 종횡비 캐시는 각각 256건이고, 넘치면 가장 오래된 항목부터 버린다. 키로 data URL 전체를 쥐고 있지 않는다(길이와 앞부분 해시만 쓴다).
- "모델에 숨김" 표시는 글자를 바꾸지 않고 글리프 런과 그림 노드에 표시로만 실어 보낸다.
- Electron을 import하지 않는다.

## 이 모듈의 방식

- 층은 `coords` → `fill` → `metrics` → `text-layout` → `build-slide` 순이다. 충실도 검증을 RenderTree에 묶어 두려는 설계이고, 그리는 어댑터는 얇게 둔다.
- 메트릭 구현은 둘이다. `OpentypeMetrics`는 실제 글꼴로 정확히 재고, `HeuristicMetrics`는 글꼴 파일 없이 글자 종류별 비율로 추정한다. 메트릭을 주지 않으면 추정이 쓰이므로 그때의 넘침 수치는 근사값이다.
- `displayFamily`는 측정에 쓴 글꼴 이름을 그리는 쪽에 알려 준다. 없는 글꼴을 대체했을 때 그리는 쪽이 브라우저 기본 대체 글꼴로 그리면, 구워 둔 x 좌표와 실제 폭이 어긋나 글자가 겹치거나 벌어진다.
- 대체된 글꼴에는 커닝을 적용하지 않는다(PowerPoint가 그렇게 한다). 치수가 호환되는 별칭 글꼴은 대체로 치지 않는다.
- 측정과 줄바꿈의 최소 단위는 코드 포인트가 아니라 자소 묶음이다. 코드 포인트로 쪼개면 결합 문자가 줄 머리로 밀리고 이모지 연속열의 폭이 여러 글자 폭으로 재진다.
- 그룹 안에서 90°/270° 돌아간 자식은, 그룹의 가로·세로 배율이 다르면 너비가 세로 배율을, 높이가 가로 배율을 따른다. PowerPoint가 회전된 겉 상자를 기준으로 늘리기 때문이다.
- 표는 PowerPoint처럼 `a:gridCol`의 폭을 기준으로 삼고 프레임의 `cx`가 낡았으면 무시한다. 행 높이는 최소값이라 줄바꿈된 글자가 더 필요로 하면 늘어난다.
- `passthrough` 요소는 미리보기가 있으면 그것으로(SmartArt는 도형 묶음, OLE는 그림), 없으면 종류를 적은 자리표시 칩(`placeholder-chip`)으로 내보낸다.
- 마스터·레이아웃에서 온 노드는 `decoration`으로 표시한다. 읽기 전용이고 선택·끌기·붙임 대상이 아니다.
- 이미지 해상도 태그(PNG pHYs, JPEG 밀도)를 읽는 이유는 PowerPoint가 타일 채움의 한 칸 크기를 이 값으로 정하기 때문이다. 태그가 없으면 144dpi로 본다.
- `bidi-js`에는 타입이 없다. 이 패키지의 소스를 직접 컴파일해 쓰는 소비자(`packages/ui`, Docs 렌더러)는 각자 선언 파일을 둔다.

## 테스트

- `npm run test -w @genoffice/pptx-render`, 또는 패키지 폴더에서 `npx vitest run`. 이 패키지에는 픽스처 폴더가 없다. 일부 테스트가 `packages/pptx-engine/tests/fixtures/`의 pptx를 엔진으로 열어 쓰고, 나머지는 슬라이드 모델 객체를 직접 만든다. 글꼴 파일을 읽는 테스트는 없다. 정확한 메트릭 경로는 가짜 글꼴 객체로 검증한다.
- vitest 별칭이 `pptx-engine`과 그 하위 경로를 소스로 묶는다. 문자열 별칭은 접두 치환이라 하위 경로를 패키지 이름보다 먼저 적어야 한다. 엔진의 새 하위 경로를 쓰면 별칭도 추가한다.
- 레이아웃 규칙을 바꾸면 좌표·줄 수·넘침 수치를 숫자로 단언하는 사례를 넣고, 방어 코드를 바꾸면 비정상 입력이 유한한 결과로 끝나는지를 넣는다.
- Windows에서 원본 코드 그대로도 실패하는 테스트는 없다.
